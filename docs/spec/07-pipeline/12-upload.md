# 7.12 ブラウザからのアップロード

ダウンロード購入した音源（mora などのハイレゾ FLAC。MP3 / AAC しか売っていないものもある）をブラウザから受け取り、
Inbox に置く。CD（[§7.2](02-cd-rip.md)）・YouTube（[§7.7](07-ytmusic.md)）と同じく、**Inbox に置くところまで**がこの節の
範囲で、承認・配置・後続（RG / Derived / 端末）は [§7.8](08-inbox.md) をそのまま使う（[D-116](../../decisions/D-116.md)）。
操作は PC のブラウザだけで、スマホ版（[§12.7](../12-ui/07-mobile.md)）には出さない。

```
① ファイルを選ぶ   zip・音声ファイル・フォルダをドロップ / 選択。選んだ時点で送り始める
② 送信             32 MiB ずつ PUT。Inbox 直下の隠しディレクトリ（ステージング）へ書く。zip は届いたら upload ジョブで展開
③ 分け方           タグで件（アルバムアーティスト + アルバム）に分け、状態を付けて返す。人がまとめる・外す
④ Inbox へ置く     公開計画を凍結し、upload ジョブが件ごとに Inbox/upload/<albumartist>/<album>/ へ rename → inbox ジョブ
⑤ Inbox で承認     既存の承認画面（§7.8）
```

モジュールは `src/import/upload/`（`manifest` / `receive` / `budget` / `unpack` / `group` / `view` / `publish` /
`reconcile`）、API は `src/api/upload.rs`（[§9](../09-http-api.md)）、ジョブは `src/jobs/handlers/upload.rs`、GC は
`src/gc/upload.rs`、画面は `components/UploadView.tsx` / `hooks/useUpload.ts` / `lib/upload.ts`（[§12.6](../12-ui/06-other-screens.md)）。

## ステージングとマニフェスト

- **置き場所**は Inbox 直下の `.spindle-upload-<16 桁の hex>/`（CD の `.spindle-rip-<DiscID>` と同じ考え方）。Inbox の走査は
  全階層で `.` で始まる名前を飛ばすので、送信途中・展開途中のものが件に見えない。公開は同じデータセットの中の rename で済む
- **中身**（利用者の名前ではなく origin ID で分けるので、置き場所で名前がぶつからない）:
  `upload.json`（マニフェスト）、`files/<origin>.part` → 受け取り終えて `files/<origin>`（ばらのファイル。元の名前と相対パスは
  マニフェストにある）、`zips/<origin>.zip`（zip 本体。公開か破棄まで残す）、`x/<origin>/g<N>/…`（zip の展開の世代。中は zip 内の
  相対パスのまま）、`publish/<n>/`（公開の組み立て）
- **状態の正はマニフェスト** `upload.json`（tmp + fsync + rename で書く。`version` 1）。DB に表を作らない
  （不変条件 1。DB を消してもマニフェストと実体から一覧・再開できる）。持つもの:
  - `origins`: 送ったもの 1 つごとの `id`（`o1`, `o2`, …。アップロード内で一意で使い回さない）、`client_path`（ブラウザ上の
    相対パス。フォルダ選択なら `Album/01.flac`、zip なら `mora.zip`）、`class`（`audio` / `zip` / `companion` / `ignored`）、
    宣言サイズ `total`、`received`、`complete`、`removed`（人が外した。件に入れないが実体が消えるまで予算に数える）、
    `damaged`（実体が食い違って壊れた）、zip は `zip: { generation, next_generation, written_bytes, unpacking, rejected, error }`
  - ③ の選択: `merges`（まとめた件のキーの組）、`excluded_files` / `excluded_groups`、`included_files` / `included_groups`
    （既定で外れるものを入れ直した記録）
  - `publish`（凍結した公開計画）、`publish_requested_at`、`publish_error`（やり直しても変わらない公開の失敗）、
    `inbox_enqueued_at`（公開より後の Inbox の走査を確保した時刻）、`discarded_at`、`created_at`、`updated_at`
  - `garbage`: GC に消させるステージング内のディレクトリ（古い・失敗した展開の世代）の `{ path, bytes, added_at }`
- **鍵**: マニフェストの読み書きは必ずアップロードごとのプロセス内の鍵（`UploadLocks` / `with_manifest`）の中で行う。同時に走る
  送信 2 本・PATCH・展開・公開・GC が同じマニフェストを読み書きしても更新を失わない。表は main が 1 つ作り、API・upload ジョブ・
  GC が共有する（別に作ると直列化が効かない）。鍵は std の Mutex なので、取る処理はすべてブロッキングのスレッドで行う。表に項を
  作るのはステージングがあると確かめてから。これはライブラリのファイルの排他ロックではない（SMB の他プレイヤーと共有しない、
  spindle だけのステージング。不変条件 5 とは別）
- **壊れたアップロード**: マニフェストの無い・読めない `.spindle-upload-*` は一覧の `broken` に出し、捨てる
  （`DELETE /api/uploads/broken/:dir` が空の印 `.spindle-discard` を置く）ことだけできる。勝手に消さず、上書きもしない。
  マニフェストは読めるが表示を作れないアップロードも、一覧全体を失敗にせず `broken` に理由を付けて出す（読めるマニフェストには
  印を付けられないので、画面は `DELETE /api/uploads/:id` で捨てる）
- **消さない**: アップロードのコードは unlink / rmdir をしない（`.part` を `offset = 0` で作り直すときの `O_TRUNC` だけは同じ
  ファイルの書き直し）。要らなくなった世代は `garbage`、捨てたものは `discarded_at` に載せ、物理削除は GC に任せる
- **パス**: ブラウザの相対パスと zip のエントリ名は [§5](../05-library-layout.md) のパス規則（`RelPath::parse`）で検証する。`\`・`..`・
  絶対パス・制御文字・空要素・`.` で始まる要素は拒否する（`\` を `/` に読み替えない）。書き込みは Inbox の root の dirfd から
  openat2（`RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS`）。名前の比較は `canonical_key`（casefold + NFD）
- **分類**（拡張子で決める）: 音声はアップロード専用の許可リスト `flac` `wav` `m4a` `aif` `aiff` `mp3` `opus`（画面の表示と同じ）、
  `zip`、同梱ファイル（`is_companion_name`。下記）、それ以外は「取り込まない」。取り込まないものも受けて保存し、③ の末尾に
  名前を出すだけで置かない（画面は隠しファイル `.DS_Store`・`._*` をはじめから送らない）。読めない音声も「取り込まない」に
  理由を付けて出す

## 送信

- **origin を作る**: `POST /api/uploads/:id/origins { path, total }`。宣言サイズをこの時点で予算に数え、空の `.part` を作る。
  同じパス（`canonical_key`）の未完の origin があれば、それを作り直して返す（ドロップし直し = 最初から送り直す。新しい origin を
  作らない）。受け取り終えた同じパスは 409 `exists`。外した・壊れた origin と同じパスは新しい origin になる
- **チャンク**: web はファイルを 32 MiB ずつ順に `PUT …/origins/:origin?offset=` で送る（外からは Cloudflare Tunnel（無料プランは
  1 リクエスト 100 MB まで）→ Nginx Proxy Manager を通るため）。サーバの本文の上限は 40 MiB（`CHUNK_LIMIT`。超えると axum の
  413 で、本文は JSON とは限らない）。同時に送るファイルは 2 つ
- **1 チャンクの処理**: 鍵の中で `.part` の実際の大きさを `offset` と照らし（違えば 409 `{ error: "offset", received }`）、追記 →
  fsync → `received` を実際の大きさにする。`total` に達したら正式な名前（zip は `zips/<origin>.zip`、それ以外は `files/<origin>`）へ
  `RENAME_NOREPLACE` → 親を fsync → `complete`。**`.part` の大きさが正**で、`received` は表示用の写し。0 バイトのファイルと
  `offset == total` の空の PUT は、受け取り終えたことの確かめとして受ける
- **実体に合わせる**（`sync_with_disk`）: 次の要求と一覧・単体の取得のたびに、未完の origin を実体に合わせる。`.part` だけがあれば
  その大きさを `received` に（`total` に達していれば正式な名前へ進めて完了に）、`.part` が無く正式な名前の大きさが `total` なら
  完了に（rename の後・マニフェストを書く前に落ちた）。それ以外の食い違い（普通の停止では起きない外部の変更・破損）は
  `damaged` にして「壊れた。外して送り直す」と出す。壊れた実体は GC まで残る
- **再開**: ファイル途中からの再開はしない。ブラウザはファイルの中身を覚えていないので、途中で止まったファイルは同じファイルを
  ドロップし直して最初から送るか、「外す」（`PATCH` の `removed_origins`。足すだけで戻さない）
- **予算はアップロード全体で数える**: 全 origin の宣言サイズ（受信中・外した・壊れたものも実体が残る間は含める）+ 全 zip の
  成功した世代で書いたバイト数 + `garbage` のバイト数（展開中の世代はここで 1 度だけ数える）が `[upload].max_upload_bytes` を
  超えるなら 413 `limit`。1 ファイルは `max_file_bytes` まで。受ける前に Inbox のデータセットの空き容量を確かめ、足りなければ
  507 `no_space`
- 公開を要求した後と捨てた後は受けない（409 `busy`）

## zip の展開

- 受け取り終えた zip は `upload` ジョブ（op `unpack`）を投入する。展開は `next_generation` を進めて永続化した**新しい世代**
  `x/<origin>/g<N>/` へ書き、成功したらマニフェストの成功した世代 `generation` を切り替える（1 回の書き込み）。古い世代と
  失敗した世代は `garbage` に入れる（展開先を先に消すことはしない）。成功した zip の展開ジョブが再実行されたら何もしない。
  展開中の世代を残したまま止まっていたら（再起動）、その世代は `garbage` に残したまま新しい世代で最初から展開する
- 鍵を持つのは始める前の検査と世代の予約、次のブロックの予約、終わりの記録だけで、zip の読みと書き込みは鍵の外
- **予算**: 書く**前に**鍵の中で次のブロック（8 MiB。予算の残りが少なければその残りまで）を展開中の世代の `garbage` の項に足して
  から書く。送信と展開が同時に走っても合計で上限を守る（予約が実際より多いぶんは安全側の誤差）。終わったら実際に書いた量に直す。
  空き容量は 64 MiB 書くごとに確かめる。取り消しと予算はエントリごとではなくコピーのバッファ（256 KiB）ごとに見る
  （巨大な 1 エントリでも止まる）
- **エントリだけ拒否して続ける**: パス規則に外れる・UTF-8 として読めない名前・symlink・特殊ファイル・`canonical_key` が先の
  エントリと衝突・ファイルとディレクトリの衝突。拒否したものは `rejected`（名前と理由）に記録し、② の zip の行の下に
  「取り込めなかった: <名前>（理由）」と出す。`__MACOSX/` 以下は展開しない
- **zip 全体の失敗**（`zip.error { reason, retryable }`）: 中央ディレクトリが壊れている・暗号化されている・対応しない圧縮方式
  （stored と deflate だけ受ける）・エントリ数が `[upload].max_zip_entries` を超える・書いた量（ヘッダの申告ではなく実際に書いた量）
  が予算を超える、はやり直せない失敗。zip を読めない・書けない（I/O、空き不足）・取り消しはやり直せる失敗。ジョブは失敗を
  マニフェストに残して `done`（note に `展開に失敗: <理由>`）で終える（取り消しは `cancelled`）。やり直せる失敗は「展開し直す」
  （`POST …/origins/:origin/unpack`）で、やり直せない失敗はその zip を「外す」ことで先へ進める

## 分け方（③）

送り終えた音声（removed でも damaged でもない `files/<origin>` と、zip の成功した世代の中身）のタグを lofty で読み（Inbox の走査と
同じ読み取り）、件に分ける（`group.rs`。純粋関数）。

- **件のキー**: ALBUMARTIST（無ければ ARTIST の先頭値）+ ALBUM が揃えばそれで 1 件（`canonical_key` で比べる）。ALBUM が無い
  ファイルは、同じ zip（origin）・同じフォルダ（ブラウザ上の相対パスの最初の要素）から来たもの同士で 1 件。ばらで送ったファイルで
  ALBUM が無いものは 1 ファイル 1 件。ハイレゾのシングル数枚をまとめて送ると、タグのアルバムごとに別の件になる
- **件のディレクトリは平ら**: Inbox の走査は「音声のあるディレクトリ 1 つ = 1 件」で、配置が持っていく同梱ファイルも件の直下
  だけなので、`Disc 1/` `Disc 2/` や `Booklet/` `Scans/` のサブフォルダは件の直下へ集める（タグが同じなら複数枚組も 1 件）。
  集めて名前が `canonical_key` でぶつかったら、元の親フォルダ名を前に付けて `Disc 2 - 01 Track.flac` にし、それでもぶつかれば
  拡張子の前に ` (2)`, ` (3)` … を付ける。曲と同梱ファイルは同じ名前空間で、サイドカーの名前 `spindle-inbox.json` は使わせない。
  ③ の開いた中に元の名前と置く名前を出す（音声の Inbox 上の名前は配置でテンプレートの名前になるので一時的。同梱ファイルは
  この名前のまま Library へ行く）
- **同梱ファイルの付け先**（表示上のパスの親ディレクトリを `canonical_key` で比べる）:
  1. 件の曲と同じディレクトリにある同梱ファイルは、その件に付ける（当てはまる件が複数なら表の先頭の件）
  2. どの件の曲とも同じディレクトリにないものは、**全曲が同梱ファイルのディレクトリの下にある件がちょうど 1 つ**ならその件に付ける
     （`Album/cover.jpg` の下に `Disc 1/` `Disc 2/` がある形。同じアップロードに別の件があっても付く）。最上位の同梱ファイルは
     全件が当てはまるので、件が 1 つのときだけ付く
  3. 当てはまる件が 0 か複数なら、どの件にも付けず ③ に「どの件にも付けない同梱ファイル」として出す（付け先を選ぶ UI は無い。
     要るなら承認の後にライブラリで足す）
- **まとめる**: 「選んだ件を 1 件にまとめる」は `merges` にキーの組を足す。まとめた件の名前（キー・アルバムアーティスト・
  アルバム）は先頭の件のもので、直すのは承認画面
- **既定のチェック**（`decide`）: 曲は既定で入れ、ライブラリに同じ音声がある曲は既定で外す。件は既定で入れ、全曲がライブラリに
  ある件は既定で外す。`included_*` が既定で外れるものを入れ直し、`excluded_*` が最後に勝つ。件を入れ直しても、既定で外れた曲は
  入らない（曲を個別に入れ直す）。入れる曲が 0 の件は入れられない（公開すると Inbox に現れないため）。同梱ファイルは既定で入れ、
  `excluded_files` だけが効く（件を入れられるかには効かない）
- **件の状態**（強い順に当たったものをすべて `statuses` に並べ、先頭を `status` に出す）:
  - `library_duplicate`（`同じ音声がライブラリにある`、赤）: 件の全曲の音声がライブラリの active な行と一致。一致は Inbox の
    再実行の判定と同じ `audio_md5`（FLAC の STREAMINFO の MD5）/ `audio_fp`（非可逆のパケット列のハッシュ）で引き、開いた中に
    一致したライブラリのパスを出す。一部の曲だけ一致する件は他の状態のままで、一致した曲だけ赤で既定で外れる
  - `inbox_exists`（`Inbox に同じ件がある`、黄）: 置き場所 `upload/<albumartist>/<album>` が Inbox にディレクトリとして既にある
    （公開すると ` (2)` の別の件になる）。Inbox の他の件との音声の一致は見ない（[D-116](../../decisions/D-116.md)）
  - `append_to`（`ライブラリの『<album>』（N 曲）に追加`、青）: 承認画面の `destination` と同じ規則（`destination_of`）で既存の
    album への追記が見込まれる
  - `needs_name`（`Inbox で名前を入れる`、黄）: アルバム名のタグが無い
  - `new`（`新規`、緑）: どれにも当たらない
- **読み直さない**: 画面は動いている間 2 秒ごとに一覧・単体を取り直すので、`StagedReadCache`（メモリだけ）がステージング内の
  ファイルごとのタグと指紋を覚え、`(inode, size, mtime)` が同じなら読み直さない。捨てた・一覧に無いアップロードの項は落とす
- 凍結した後はファイルが `publish/<n>/` へ移っていくので、ステージングは読まず計画（件ごとの段階と宛先）だけを返す

## Inbox へ置く（公開）

- **凍結**: `POST /api/uploads/:id/publish` は、その時点の分け方から公開計画を作ってマニフェストに凍結し（`publish`、
  `publish_requested_at`）、`upload` ジョブ（op `publish`）を投入する。計画は件ごとに番号 `n`、件のキー、アルバムアーティスト・
  アルバム・未タグの件の名前、元の名前、メンバー（ステージング内の元の場所と置く名前）、段階を持つ。入るのは入れる件と、その入れる
  曲・同梱ファイルだけ。以後 ③ の変更と「捨てる」は受け付けない。押し直し（二度押し・再起動後）は計画を変えず、同じジョブを
  投入し直すだけ（冪等）
- 凍結の条件: 外していない origin に送信未完・未展開・展開中・失敗した zip があれば 409 `incomplete`。入れる件が 0 なら
  409 `empty`。壊れた（damaged）origin は外したものと同じ扱いで、凍結を止めない（③ に「壊れた」と出ているので、残すなら送り直す）
- **段階**（件ごと。各段階の実体の操作とその段階のマニフェストの書き込みを同じ鍵の中で行う。再実行は計画と実体だけで続きから進む）:
  1. `planned` → **組み立て**: `publish/<n>/` へメンバーを `RENAME_NOREPLACE` で移し（元に無く組み立て先にあれば移し済み）、
     サイドカー `spindle-inbox.json` に `upload` の記録（`upload_id`、`group_key`、凍結した時刻 `uploaded_at`、元の名前 `origins`）を
     書き、ディレクトリを fsync → `assembled`
  2. `assembled` → **宛先の確定**: 置き場所の基本の名前（アルバム名があれば `upload/<albumartist>/<album>`、無ければ
     `upload/_untitled/<zip 名かフォルダ名かファイル名>`。各要素は `sanitize_component` の後、`.` で始まれば `_` を前に付け、
     200 バイト以下に文字境界で切る。走査が飛ばす隠し名や長すぎる名前にしない）が埋まっていれば ` (2)`, ` (3)` … の最初の空き
     名を選び、**宛先をマニフェストに書いてから**（`publishing { dest }`）rename する
  3. `publishing` → **公開**: 宛先の親を作り、`publish/<n>/` を宛先へ `RENAME_NOREPLACE` → 親を fsync → `published { dest }`。
     `publish/<n>/` が無ければ rename は済んでいる（宛先が既に Inbox の配置で消えていてもよい）。宛先が他に取られていれば
     `assembled` に戻して名前を選び直す
- 既存の件に混ぜない: 置き場所が既にあれば ` (2)` の別のディレクトリにする（同じ名前の Inbox の件へ足すと、人が見ていない
  ファイルが承認済みの件に混ざる）
- **走査の確保**: 全件が公開済みになったら `inbox` ジョブを投入し、**公開より後に走る走査を確保できたときだけ**
  `inbox_enqueued_at` と `discarded_at` を入れる。新しく投入できた・待ち（queued）の inbox ジョブがあれば確保できている。実行中
  （running）の inbox ジョブと重なったら（既に歩き終えて新しい件を見ないかもしれない）、記録せずに公開ジョブを 5 秒後に
  やり直す。記録の前に落ちても照合が投入し直す。ジョブの note は `Inbox へ置いた: N 件` と置いた dir の行（画面の ⑤ が使う）
- **止まった公開**: やり直しても変わらない失敗（状態が合わない・パスが不正など）は `publish_error` に残し、照合は投入し直さない
  （取り直しのたびに失敗するジョブを作らない）。押し直しが `publish_error` を消して投入し直す。`publish_error` があって upload
  ジョブが動いていなければ捨てられる（そうしないと押し直すしかなく永久に残る）
- 外したファイル・件・取り込まないファイルはステージングに残り、公開で入った `discarded_at` から GC が消す。ジョブは各段階の前に
  `discarded_at` と取り消しを確かめる

## 照合とジョブ

- `upload` ジョブ（並列 1。payload `{ upload_id, op: "unpack", origin, retry }` / `{ upload_id, op: "publish" }`、dedup キー
  `upload:<id>:unpack:<origin>` / `upload:<id>:publish`）。どちらも冪等で、再起動で `queued` に戻って最初から走ってよい
- **照合**（`reconcile`）: マニフェストを正として、取りこぼしたジョブを投入し直す。起動時（リカバリの後・ワーカーの起動の前）と
  一覧・単体の取得のたびに走り、投入したらワーカーを起こす。対象は捨てていないアップロードの、受け取り終えて未展開で失敗して
  いない zip（外した・壊れたものを除く）と、計画があって `inbox_enqueued_at` も `publish_error` も無いもの。DB が消えても、
  ジョブを投入する前に落ちても、ここで拾える
- 展開・公開のジョブが queued / running の間（`upload_busy`）と、公開を要求した後・捨てた後は、`PATCH` と `DELETE` を 409
  `busy` にする（実行中の処理と捨てる・分け方の変更が競合しない。`publish_error` の例外は上記）

## GC

GC の区分 G（`src/gc/upload.rs`。物理削除するのはここだけ）。保持は `[gc].retention_days`。

- (a) `discarded_at` から保持期間が経ったステージング（公開後の残り・捨てたもの）をステージングごと消す
- (b) マニフェストの無い・読めないステージングで、ディレクトリの mtime から保持期間が経ったものを消す（読めるマニフェストに
  印だけがあるものは消さない）
- (c) 生きているアップロードの `garbage` の項で、実体の mtime から保持期間が経ったもの（展開中の世代は除く）を消して項を外す
- (d) 放置: 公開も破棄もされず `updated_at` から `[upload].stale_days`（既定 30）経ったものに `discarded_at` を入れるだけ
  （消すのは後日の (a)）。API は期限を `expires_at` で返す。公開が止まったもの（`publish_error`）は放置の対象にしない
- 計画時の根拠（id、`updated_at`、`discarded_at`、ディレクトリの stat）を持ち、**消す直前にアップロードの鍵を取って読み直し**、
  変わっていれば何もしない（[D-90](../../decisions/D-090.md) と同じ）。ステージングごと消すときは鍵だけを取り（マニフェストは書き戻さない。
  `upload.json` は最後に消す）、`garbage` と放置は `with_manifest` の中で行う。結果は gc の note に `アップロード N（バイト数）`
  と `放置したアップロードを破棄扱い N`

## 同梱ファイルの拡張

`cd::riplog::is_companion_name` に **PDF（`*.pdf`）と画像（`*.jpg` / `*.jpeg` / `*.png` / `*.webp`）** を足した（購入音源に付く
ブックレットや追加の画像を、ライブラリのアルバムのフォルダへ一緒に持っていくため）。これを使うのは Inbox の配置（[§7.8](08-inbox.md)）、
却下した件の削除（GC の区分 F、[D-90](../../decisions/D-090.md)）、一括リネームの同梱ファイルの追随（[§7.2](02-cd-rip.md)）で、どれも足した
形式に同じ規則で効く（CD・手置き・YouTube の件も同じ。既に却下済みの件の PDF・画像も削除の対象に入る）。アートワークの選び方
（`cover_rank`）は変えない。

## 不変条件との関係

- ファイルが正: 件の情報はサイドカー、アップロードの状態はマニフェストと実体が正で、DB に表を持たない。ジョブ行が消えても
  照合が投入し直す
- 物理削除は GC だけ（捨てる・外す・放置は論理削除）
- 承認を経ずに Library へ入らない（公開先は Inbox）
- ライブラリのファイルを排他ロックしない（マニフェストの直列化は spindle だけのステージングに対するプロセス内の鍵）
- ジョブは冪等（展開は世代を切り替え、公開は凍結した計画と段階で続きから進む）
- 非可逆 → 非可逆の再エンコードはしない（MP3 / AAC はそのまま置く）
