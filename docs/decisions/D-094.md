## D-94 CD の取り込みで品番（と JAN）を手で入れ、版の識別と照会に使う

**決定**（2026-09-26。P4-25。ユーザの要望: 「挿入した CD は通常盤なのに、MusicBrainz で一致したのは初回限定盤で、
そのまま取り込むとどの盤かという情報が落ちる。見た CD にはすべて品番（UPCJ-9085 のような）が付いていたので、
取り込み時に手で入れて保持すれば、後で版を直せる」。下の形をユーザが選んだ）:

- **CD 画面の ① に「品番」と「JAN」の入力欄を置く（どちらも任意）。** 値の補正ではなく照会と識別の入力で、
  D-67 追記の「CD 画面からは直せない」の例外にする（他の値は従来どおり Inbox の承認画面で直す）。
  入力は盤が替わったら消す
- **照会**: `POST /api/cd/lookup` に `catno?` を足す。リリース URL / MBID と同じく**段に関係なく常に引く**
  （DiscID で当たっても引く。通常盤と初回盤は収録が同じなら TOC も同じで、DiscID では版を区別できないため）。
  `ws/2/release?query=catno:"…"`（値は英数字・ハイフン・空白だけを通し、Lucene の記号を通さない。取得の上限は
  バーコードと同じ 3 件）。検索は大文字小文字・ハイフンの揺れを吸収するが部分一致もありうるので、リリースの
  label-info の品番のどれかが入力と**正規化して一致する**（大文字小文字・ハイフン・空白を無視）ものだけに
  経路 `catno` を付ける。JAN は既存の `barcode:` の検索に、盤から読めた MCN が無いときの入力として渡す
- **候補の並び**: 品番の入力があるときは、経路 `catno` を持つ候補を先頭にする（既定で選ばれる）。
  `matched_by` の強い順は `catno | discid | release | isrc | barcode | toc`。品番は実物から読んだ版の識別子で、
  DiscID が別の版にしか登録されていない盤では、品番で当たった版が手元の盤になる。収録の違う版
  （ボーナストラック付き等）は DiscID 自体が変わり、トラック数の合わない候補は従来どおり落ちる
- **下書きへの写し方**（写す範囲が「最小限」でも、入力した品番と JAN は書く。ユーザが実物から読んだ値のため）:
  - 選んだ候補の品番が入力と一致する → `CATALOGNUMBER` は候補の表記、`BARCODE` は候補の値
    （JAN の入力があり食い違えば入力値）
  - 食い違う（MusicBrainz に手元の版が無く、別の版で取り込む）→ 画面に注意を出し（例:「この候補の品番は
    UPCJ-9001（初回限定盤A）で、入力した品番と違います」）、版に固有の値を引き継がない:

    | タグ | 扱い |
    |---|---|
    | `CATALOGNUMBER` | 入力値 |
    | `BARCODE` | 引き継がない（JAN の入力があればそれ） |
    | アルバム名・アーティスト・トラック名・ISRC・`MUSICBRAINZ_TRACKID` | 引き継ぐ（DiscID / ISRC で中身が同じと確かめている） |
    | `LABEL`・`DATE` | 引き継ぐ（通常盤と初回盤で違うことはまず無く、日付も年はほぼ合う） |
    | `MUSICBRAINZ_ALBUMID`・`MUSICBRAINZ_RELEASETRACKID`・`MUSICBRAINZ_RELEASEGROUPID` | 引き継ぐ（近い版を指す値として） |
- **版がずれている印は DB に持たない。** `CATALOGNUMBER` が `MUSICBRAINZ_ALBUMID` のリリースの品番に無いことが
  印になり、タグと MusicBrainz から後で拾える（ファイルが正）。拾って版を直す画面は今回は作らない

**理由**: 実機で 7 枚取り込んだところ、DiscID で当たった候補が手元の盤と別の版のことがあった。DiscID は TOC から
出るので、収録が同じ版どうしは区別できない。品番は盤に必ず印刷されていて手入力の手間も小さく、MusicBrainz の
`catno:` 検索で版まで決まる（2026-09-26 に `catno:UPCJ-9001` → 「シンデレラガール」初回限定盤A の 1 件、
`catno:upcj9001` でも同じ 1 件を確認）。MusicBrainz に手元の版が無くても、品番がタグに残れば後で直せる。

D-72 の「カタログ番号や JAN は要らない」はこの範囲で覆す（値としてではなく、版の識別子として要る）。
D-72 の Discogs の却下はそのまま残す。品番の入力を入れたあと、MusicBrainz で当たらない盤がどれくらいあるかを
見て再検討する（TASKS の残課題）。

**却下**:
- 品番を「補助」に留め、DiscID / ISRC で当たった候補を常に優先する（収録が同じ版を区別できないので、
  品番で手元の版が見つかっても初回盤で取り込まれる）
- 食い違うとき `MUSICBRAINZ_ALBUMID` も外す（版に固有なので筋は通るが、ライブラリにあるかの判定（D-85）と
  ジャケットの自動取得（D-91 / D-93）が効かなくなる。品番との食い違いが後で版を直す手がかりとして残る）
- 食い違うとき候補の JAN を残す（品番が違えば JAN も別物で、実物と違う値がタグに残る）
- 版がずれている印を DB やサイドカーに持つ（タグと MusicBrainz から導ける。マイグレーションに見合わない）
- レーベルの公式サイトやタワーレコード / HMV を品番で引く（公開 API が無くスクレイピングになり、サイトごとに
  解析が要って改修で壊れる。規約上も自動取得は想定外）
