## D-112 Derived のバッジは系統ごとに O（opus）と A（aac）を並べ、凡例の高さは窓の下端までにする

**背景**（2026-10-17）: Library の表の D バッジは opus の系統だけを見ていた（aac は D-75 で後から足し、プロパティでだけ見せて
いた）。iPhone への配信（Mac のエージェント）で aac も日常的に使うようになり、aac の Derived があるか・タグが追いついているかを
表で見たい。また、凡例のポップオーバーは高さを固定の `70vh` で切っていたため、上のプロパティ欄が高く表のツールバーが下に
あると、凡例の下端が窓の外に出て最後まで読めなかった（ページ自体はスクロールしない）。

**決定**:

1. Derived のバッジは系統ごとに 1 つ。`opus` は **O**、`aac` は **A**（この順）。タグ版が古い（`stale_tags`）ときは点付き
   （O• / A•）。どちらも同じ色（`b-derived`）。バッジの key は `derived-opus` / `derived-aac`
2. `has_derived`（DSL / フラグ）は従来どおり `opus` 系統の行の有無（配布ビューの意味を変えない）
3. 凡例は開いたとき・窓の大きさが変わったとき・位置決めの親（ツールバー）とその親（表）の大きさが変わったとき
   （`ResizeObserver`。開いたままプロパティ欄の高さを変える・ツールバーが折り返す）に、自分の上端から窓の下端（余白 8px）
   までを `max-height` にする。残りを超える下限は置かない。中は凡例自身がスクロールする
4. 凡例は O / O• / A / A• をそれぞれ 1 行に載せる

**理由**: 系統の区別は 1 文字で足りる（D のままでは aac が分からない）。凡例は配置（ツールバーの位置）が利用者の欄の高さで
変わるので、固定の比率では収まらない。

**却下**: 凡例を `position: fixed` の中央のダイアログにする（「凡例」ボタンの直下に出る今の操作感が変わる）。
