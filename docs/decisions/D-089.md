# D-89 ALAC のプロセス内デコードの範囲を本番の ffmpeg に揃える（MP4 の edit list と末尾の長さ 0 のサンプル）

**現行の規則は末尾の追記（2026-09-26）。** 以下の「旧決定」（宣言長で打ち切る）は追記で廃止した。

**旧決定（追記で廃止）**（2026-09-24。リハーサルの FLAC 正規化で見つかった不一致への対応）:

- symphonia のデコード出力を、**ALAC のトラックに限り**宣言長（`Track::num_frames`）で打ち切る
  （`media::fingerprint::FrameLimit`）。対象は `decoded_pcm_md5`（`audio_md5`、正規化の照合値、MD5 補填）、
  `decode_s16`（CD の CRC）、`media::decode` のプロセス内経路（RG / 偽ハイレゾ検出）。宣言長が無いトラックと、
  delay / padding を持つトラックは打ち切らない。ffmpeg の経路は ffmpeg 自身が打ち切るので変えない
- ALAC 以外に広げない。symphonia 0.6.1 の MP4 は edit list を読まず、AAC の encoder delay も
  `delay` / `padding` に載せないので、AAC の `num_frames`（`stts` の合計）は trim 前の長さでも再生長でもない
  （1 秒 / 44.1k の AAC で num_frames 45,124、symphonia のデコード 46,080、ffmpeg 44,100）。打ち切ると
  AAC の RG 値が中途半端な長さで変わるだけなので、従来の出力（46,080）を保つ（codex レビューの指摘）。
  FLAC / WAV / AIFF は宣言長とデコード長が一致するので掛けても値は変わらないが、必要が無いので掛けない
- ALAC を ffmpeg でデコードする経路には変えない。デコーダの構成（symphonia 優先・Opus は ffmpeg）はそのまま

**原因**: リハーサル環境の正規化で ALAC 7 本（24 bit の 48k / 96k）が「変換前後の PCM MD5 が一致しない」で
失敗した（照合が働き、元ファイルは無傷）。これらの MP4 は `stts` が `[(N, 4096), (1, 0)]` で、最後のサンプルの
長さを 0 と宣言している（`mdhd` の duration も N×4096）。ffmpeg は宣言どおりそのサンプルを捨てるが、
symphonia 0.6.1 の MP4 読みはパケットとして返し、デコーダは 1,043〜1,664 フレームを余分に出す。
共通部分の PCM はビット単位で一致しており（内容の違いではなく長さの違い）、余分な部分はほぼ無音
（1 本は全 0、1 本は最大でも −101 dBFS 程度）。宣言長で打ち切ると 2 本とも ffmpeg と同じ MD5 になる。

**理由**: ユーザは当初「ALAC のデコードを ffmpeg に揃える」を指示したが、正規化は元ファイルを symphonia、
生成物を ffmpeg で読んで突き合わせる（[D-46](D-046.md)「独立した 2 つのデコーダ」）ので、ALAC を ffmpeg にすると照合が
自己比較になって安全弁の意味を失う。原因が長さの宣言の解釈だけで、symphonia の PCM 自体は正しいので、
宣言長に従わせる方が変更も小さく照合も保てる。ユーザはこの案を選んだ。

**既存 DB への影響**: 該当する ALAC（末尾に長さ 0 のサンプルを持つもの）は次の deep scan で `audio_md5` が
変わり、`audio_version` が上がって RG と Derived が自動でやり直される。それ以外の ALAC / FLAC / WAV / AIFF は
宣言長 = デコード長なので値が変わらない。AAC / MP3 / Opus / Vorbis は打ち切りの対象外で値が変わらない。

**却下**: ALAC だけ ffmpeg でデコードする（照合の独立性を失う。同期の呼び出し元に外部プロセスを通す変更も大きい）。
正規化の照合で長さの差を許す（本物の欠損・切り詰めも通してしまう）。

**追記（2026-09-26。本番の再移行で見つかった打ち切りすぎ。ユーザ依頼）**: 本番の再移行の FLAC 正規化で、ALAC 46 本が
逆向き（symphonia の方が短い）の不一致で止まった。上の「ffmpeg は宣言どおり捨てる」は誤りで、ffmpeg は `stts` ではなく
edit list（`elst`）に従っていた。上の 7 本は `elst` の終端が宣言長ちょうど、46 本は `mvhd`（1/1000 秒）への切り上げで
3〜64 サンプル後ろにあり、長さ 0 のパケットの開始（= 宣言長）が終端より前なので ffmpeg はそれを丸ごとデコードしていた。
46 本の余分は 64〜4,096 フレームで、43 本は無音か −100 dBFS 以下、3 本は −53〜−83 dBFS のフェードの末尾（本物の音声）。
上の回帰試験のフィクスチャ（`stts` と `mdhd` だけを縮める）も終端が後ろの形で、ffmpeg は実際には捨てていなかった。

- **本番の ffmpeg（5.1）の規則**（実 ALAC と、実 ALAC から stream copy・`elst` の書き換えで作った形で確かめた）:
  先頭は media_time サンプルちょうど削る。終端は media_time + 区間の長さ（movie timescale → media timescale を
  四捨五入。端数 0.4 は切り捨て、0.5 は切り上げ）。終端以降で**始まる**パケットは捨て、終端をまたぐパケットは
  丸ごと残す（長さ 0 のパケットも同じ規則）。edit list が無ければ何も削らない。「空の編集 + 区間」の 2 項
  （出力側 `-ss` の stream copy が書く）は edit list を無視して全パケットを出す
- **ffmpeg の版で違う**: 新しい ffmpeg（開発機の N-125084、2026-06）は終端で端数を切り（長さ 0 のパケットだけは丸ごと）、
  「空の編集 + 区間」では末尾を空の編集の長さだけ削る。先頭の削り・終端 = 全パケットの終わりの形・長さ 0 の
  パケットの扱いは 5.1 と同じ
- **決定**: `FrameLimit` を「宣言長で打ち切る」から「本番の ffmpeg 5.1 の出力範囲を再現する」に変える。ALAC で、
  `elst` が 1 区間・media_time ≥ 0・等速・長さ > 0 のとき、先頭を media_time 削り、終端以降で始まるパケットを読まない
  （`media::mp4edit` で `moov` から読む。symphonia は edit list を読まないため）。`elst` が無い・単純な形でない・
  `mdhd` の timescale がサンプルレートと違うときは何も削らない（「空の編集 + 区間」は 5.1 と一致する）。
  edit list は symphonia が選んだトラック（`Track::id` = `tkhd` の track ID）のものだけを使う（symphonia は codec の
  分かる最初の音声トラックを選ぶので、先頭の音声トラックとは限らない）。壊れた・悪意のあるファイルで膨らまないよう、
  `moov` 64 MiB・トップレベルの箱 64 個・音声トラック 8 本・保持する `elst` の項 4 件を上限にし、子の箱は確保せずに辿る
  （codex のレビューの指摘）
- **理由**: 正規化の照合（[D-46](D-046.md)）は元ファイルを symphonia、生成物を本番の ffmpeg で読むので、両者の出力範囲が同じでないと
  必ず失敗する。46 本の余分を捨てる（FLAC 側も宣言長で切る）とフェードの末尾（最大 85 ms）を失い、ALAC のまま残すと
  正規化の対象から恒久的に外れる。ユーザは ffmpeg の実際のデコード長に合わせる案を選び、実在しない形（先頭の削り・
  終端がパケットの途中や手前）も実 ALAC で確かめながら再現するよう指示した
- **確かめたこと**: 実 ALAC 53 本（上の 7 本と 46 本）と、実 ALAC から作った 31 の形、長さ 0 のサンプルを持たない
  `elst` 付きの実 ALAC 9 本で、`decoded_pcm_md5` が本番コンテナの ffmpeg 5.1 で作った FLAC の STREAMINFO MD5 と一致
- **ffmpeg を上げるとき**（ベースイメージの Debian を上げると 7.x になる）: 終端をまたぐパケットと「空の編集 + 区間」の
  扱いが変わる。実在する形（edit list が無い・終端 = 全長・長さ 0 のパケット）は版で変わらないので既存の 46 本 + 7 本は
  影響を受けないが、変わる形のファイルは照合で止まる（音声は失わない）。そのときは `FrameLimit` を新しい版の規則に
  合わせ、`tests/fingerprint.rs` の 5.1 に固定した期待値を直す
- **既存 DB への影響**: 46 本は次の deep scan で `audio_md5` が変わり、`audio_version` が上がって RG と Derived が
  その 46 本だけやり直される。7 本の形と、edit list を持たない ALAC は値が変わらない
- **却下**: 正規化の照合で末尾の差を許す（本物の欠損・切り詰めも通してしまう）。ALAC を ffmpeg でデコードする
  （本文と同じく照合の独立性を失う）。新しい ffmpeg の規則に合わせる（本番は 5.1 で FLAC を作る）
