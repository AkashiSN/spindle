## D-111 Derived のジョブは、行った処理（エンコード / タグ更新 / 移動）を結果列に出す

**背景**（2026-10-17）: タグの一括編集の後、ジョブ画面に「Derived 生成 … 実行中」が並び、再エンコードが走っているのか
タグの書き換えだけなのかが画面から分からなかった。`transcode` は 1 種類のジョブで、ハンドラが実行時に現在値から処理
（`Plan`）を決めるので、種別の名前では見分けられない。

**決定**:

1. `Plan` ごとの名前を持つ（エンコード / タグ更新 / 移動 / 移動 + タグ更新 / 変更なし / 対象外）
2. 処理を決めて Derived のパスを予約した後、実行の前にその名前を `jobs.note` に書く（`running` の行だけ）。ジョブ画面は
   既存の結果列（`note` の 1 行目）で、実行中の行にも名前を出す。書けなくても処理は止めない
3. 完了時は実際に行った処理を `DoneWith` で残す。移動・タグ更新が Derived の消失でエンコードに倒れたときは、エンコードが
   自分で「エンコード」を書いて返す。何もしなかったジョブは「変更なし」「対象外」
4. 再キュー（パスの予約が取れない・世代が動いた）では `note` を消さない。次の実行が書き直す
5. ハンドラに入る前にワーカーが stale（版が進んだ・トラックが無い）として no-op で終えるときは、`JobType::noop_note`
   （transcode だけ「変更なし」）で `note` を**置き換える**（`COALESCE` で前の試行の処理名を残さない）。他の種別は従来どおり
   `note` に触らない

**理由**: 新しい列や SSE の詳細を足さずに、既存の `note` と結果列（D-106）で足りる。一覧は job イベントのたびに DB から
取り直すので、長いエンコードは進捗のイベントで実行中の名前が見える。タグ更新は数秒で終わるので、完了時の `note` で見える。

**却下**: 投入時にジョブの種別を分ける（処理は実行時の現在値で決まり、投入時の判断は古くなる。dedup の鍵も変わる）。
