# D-87 YouTube 画面と一括編集・操作タブにも番号付きの段の導線を入れる

**決定**（2026-09-24。ユーザ要望。モックで合意）:

- **YouTube 画面は「ダウンロード」と「購読」を切り替え、どちらも番号付きの段にする。** ダウンロードは
  ① URL → ② 取り込み方 → ③ ダウンロード → ④ Inbox で承認、購読は ① 再生リスト → ② アルバムとして登録 →
  ③ 登録して同期。④ は置いた件を並べて「Inbox で開く」だけにし、承認そのものは Inbox の画面で行う
  （承認画面を二か所に作らない）
- **① で取り込み済みかを先に見せる**（`POST /api/ytmusic/lookup`。DB だけ）。動画は正規形
  `https://www.youtube.com/watch?v=<id>` にしてファイルの `SOURCE_URL` と照合する（ダウンローダの判定と同じ）。
  `list=` 付きの動画 URL は yt-dlp と同じく再生リストとして扱う。YouTube 以外の http / https は照合せずに
  そのまま投入する（yt-dlp の対応サイトは広い）。照合は目安で、投入側の飛ばし（[D-70](D-070.md)）はそのまま残す
- **再生リストの中身は別の API で引く**（`POST /api/ytmusic/playlist`）。yt-dlp の列挙は数秒かかりネットワークに
  出るので、照合（毎入力）とは分けて URL ごとに 1 回だけ呼ぶ。読むだけでジョブにしない。同時に 2 本まで、
  90 秒で打ち切り、接続が切れたら yt-dlp も止める。新規が 0 の再生リストは投入しない（取りこぼしがあれば投入する）
- **③ ④ が追う「今回の投入」はサーバが返したジョブと、その展開の子に限る。** 再生リストの展開が投入する
  ytdl の payload に `parent_job_id` を入れる（ハンドラは読まない）。id の大小で「以降」を今回とみなすと、
  購読の同期や別の画面の投入、重複で返った古い id 以降の履歴まで混ざる（codex 指摘）
- **一括編集・操作タブは段を横に 4 列並べる。** パネルは表の上で高さが 260px 前後の横長なので、縦に積むと
  スクロールが要る。コンテナ幅が狭ければ 2 列 → 1 列
- **操作タブは操作を 1 つ選ぶ形にする。** これまでは全部の操作を縦に並べていたが、③ と ④ をその操作用にし、
  「巻き戻せる変更 / ジョブ / 読むだけ / すぐ反映」を印で示す。④ は押せない理由（プレビュー待ち・画像未選択・
  追加先未選択）を添える
- **操作タブで操作を切り替えたら、前の操作の結果・失敗・反映待ちの確認を消す。実行中は切り替えない。**
  反映待ちの「除外して適用」は保持中の操作をやり直すので、別の操作の段に出ると別の操作を実行してしまう
  （codex 指摘）
- **プレビューが古くなったことを見せる。** これまでは古いプレビューを黙って消していた。③ を「古い」にして
  枠を警告色にし、④ を押せなくする（`useBatchEdit.stale` / `useOperations.pathStale`）

**理由**: CD / Inbox で入れた導線（[D-85](D-085.md)、[D-86](D-086.md)）を他の取り込み・編集の画面にもそろえ、どこまで済んだか、
次に何をするかを同じ形で読めるようにする（ユーザ要望）。

**却下**: YouTube ④ で承認まで済ませる（Inbox の承認画面と重複する）。操作タブを全部並べたまま段だけ付ける
（操作ごとに ③ ④ の中身が違い、段が意味を持たない）。再生リストの列挙を照合 API に含める（入力のたびに
yt-dlp が走る）。
