## D-113 Inbox の承認で種類（TRACK_TYPE）と除外（PLAYLIST_EXCLUDE）を選び、タグのキーの入力欄に前方一致の候補を出す

**背景**（2026-10-17）: プレイリストの運用を「曲の性質はファイルのタグ（`TRACK_TYPE` = karaoke / bgm / drama / talk、
曲だが外したいものは `PLAYLIST_EXCLUDE=1`）で持ち、00_<category> とシリーズのプレイリストはそれを除くスマートプレイリスト」に
した。取り込みはどの経路（CD / YouTube / 手置き）も Inbox の承認を通るので、そこで付ければプレイリストと端末の配信が
自動でついてくる。ただし任意のキーを「タグを追加」で手入力するのは手間で、付け忘れると曲でないものが紛れ込む。
タグのキーの入力欄（Inbox のタグの追加・プロパティのフィールドの追加・一括編集）は、ライブラリでどんなキーが
使われているかが分からず、綴りを覚えておく必要があった。

**決定**:

1. Inbox の承認の表に**種類**（選択欄: 曲（空）/ カラオケ / BGM / ドラマ / トーク。値は karaoke / bgm / drama / talk）と
   **除外**（チェック。`PLAYLIST_EXCLUDE=1`）の列を置く。中身は既存の下書きのタグ（D-86）なので、サーバの変更は無い。
   汎用のタグの列には出さず、「タグを追加」でこの 2 つのキーを足そうとしたら列を案内する。知らない値（手で書いたもの）は
   選択欄にそのまま出す
2. 種類が空の行に候補を出す（`suggestTrackType`）。タイトルの instrumental / inst. / off vocal / karaoke / カラオケ / 歌無し /
   without vocal / backing track → カラオケ、ドラマ / drama / ボーナス・トラック → ドラマ、MC（番号だけ）/ ラジオ / トーク /
   コメント / DJトラック → トーク、アルバム名がサウンドトラック / サントラ / soundtrack / OST / Music Collection / 劇伴で、
   トラックのアーティストがアルバムで一番多いアーティスト（作曲者とみなす）なら BGM。**候補は自動では入れない**。
   行の「候補: …」か表の上の「種類の候補をすべて適用」で人が入れる
3. `GET /api/tags/keys` でライブラリにあるキーと曲数（missing と `PICTURE` を除く、曲数の多い順）を返す。入力欄は
   フォーカスしたときに取り（30 秒は使い回す）、よく使うキー（`COMMON_KEYS`）のうちライブラリに無いものを後ろに足し、
   入力のたびに**前方一致**（大小文字を区別しない）で絞って出す。既にあるキー（Inbox の列・プロパティの行）は除く。
   ↑↓ で選び Enter / Tab かクリックで入れ、Esc で候補を閉じる。候補を選んでいないときの Enter / Esc は従来どおり
   （追加の確定・取り消し）。共通の部品 `TagKeyInput` を 3 か所で使う

**理由**: 取り込み時に付けるのが一番漏れにくく、承認の画面ならどの経路も通る。候補を自動で入れないのは、誤判定（曲名に
「ラジオ」を含む歌など）がそのままファイルに書かれるのを防ぐため。キーは数十種類しか無い（本番で 34）ので、打つたびに
サーバへ問い合わせず、一覧を取って手元で絞るほうが速い。

**却下**: 候補を下書きの初期値として入れる（確認せずに承認すると誤判定が書かれる）。CD の取り込みの画面にも同じ欄を置く
（CD も Inbox の承認を通るので二重になる）。部分一致（キーの途中）で絞る（`TRACK` で `TOTALTRACKS` まで出て、狙いの候補が
埋もれる）。
