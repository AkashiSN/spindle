# D-104 Mac の `pair --adopt` はサーバの行の uuid を差し替え、adopt API が付け替えた状態をキャッシュへ直接書く（D-103 の 7 を改める）

**背景**（2026-10-13。P5-8。仕様は [§7.11](../spec/07-pipeline/11-device-delivery.md) の「iPhone」の「引き継ぎ」）: [D-103](D-103.md) の 7 は、エージェントが state の `(track_id, path, rel_path, source)` とプレイリスト名を送って付け替え表を受け取り、state のキーを直して `needs_report = true` で `report_only` する、としていた。作る段で調べると、DB を作り直した直後は `source_hashes` が無く、送る元のハッシュが揃うまで曲が desired に入らない。`device_items` も空なので、報告の各項目は「現在の desired」「既存の `device_items`」「計画で許された遷移」のどれにも一致せず、検証（`src/device/report.rs`）を通らない。また DB を失うと Mac の端末行（uuid・トークン）も消え、新しい行は新しい uuid を持つが、エージェントの state と `~/Music/spindle/.spindle-device` は旧 uuid のままなので、uuid をどちらに揃えるかも決める必要があった。

**決定**:

1. **pair の `adopt_uuid` で、サーバの行の uuid を前の登録（state）の uuid へ差し替える**。`agent_proto::PairRequest` に `adopt_uuid: Option<String>`（`#[serde(default)]`）を足す。形（32 桁の小文字 16 進）はコードに触る前に確かめ、外れたら 400 `bad_request`。差し替えはコードの消費と同じトランザクションで、行が端末の状態を一度も持っていない（`last_synced_at` が NULL、計画が 1 件も無い、`device_items` と `device_playlist_state` が空）うえ `adopt_uuid` が他の行に無いときだけ許す。行の uuid が既に `adopt_uuid` なら、報告も計画も無い（`last_synced_at` が NULL、計画が 1 件も無い）ときだけ差し替え済みのやり直しとして通す。`device_items` / `device_playlist_state` は見ない（前の adopt がキャッシュを書いた後、エージェントが付け替えを保存する前に落ちたやり直しを通すため）。報告か計画があれば DB を失っていない端末で、通すと `adopt_pending` が下りないまま adopt が 409 を返し続けるので断る（その端末は `--adopt` 無しの pair で入れ直す）。`agent_selector` はコードの発行で NULL に戻るので条件にしない。それ以外は 409 `not_adoptable` で、コードは消費せず、検証の前に予約した試行の枠も返す（`refund_pair_attempt`。コード自体は正しかったので試行の上限に数えない）
2. **`POST /api/agent/adopt` が付け替えた状態をキャッシュへ直接書く**（報告を通さない）。本文は state の曲（`track_id`・パス・`rel_path`・`source`・size・sha256・`stale`）とプレイリスト（`playlist_id`・名前）。検証は報告と同じ水準（件数の上限、パスの形、既知の `source`、id とパスの鍵の重複、空の名前。加えて sha256 は小文字 16 進 64 桁で、空（中身を失った曲）は `stale` のときだけ許す、size は i64 に収まること）で 400 → スキャン中なら 409 `library_busy`（`adopt_snapshot`）→ 書き込みのトランザクションの中で open な計画があれば 409 `open_plan`、`last_synced_at` が NULL でなければ 409 `not_adoptable` の順に確かめる。付け替えは Android と同じ規則（`remap_ids` に切り出し、manifest の `remap` もそれを使う）。書くのは `device_items`（トークンは `stale` なら `STALE_TOKEN`、それ以外は `ADOPTED_TOKEN`）・`device_playlist_state`（`dest_path` は名前、トークンは `STALE_TOKEN`）の全置換と印の付け足し（既存の印は外さない）で、`device_errors` は空にする。`generation` と `last_synced_at` は進めない。冪等で、応答は付け替え表（外れたものは `to: null`）
3. **エージェントの `pair --adopt`**: コードを使う前に、通常の pair の前提、前の登録の state（初期化が済みサーバの情報がある）、root の `.spindle-device` の照合、ローカルの回復を通し、`pending_ops` / `pending_batches` が残れば止める。pair の後は新しいトークンで adopt を送る。トークンを保存する前に `adopt_pending = true` とサーバの URL・名前を保存し（逆順だと間で落ちたとき新しいトークンと付け替え前の state が組み合わさり、次の sync が付け替えずに差分を出す）、付け替え（キーの付け替え、曲のトークンを `ADOPTED_TOKEN`（`STALE_TOKEN` はそのまま）、プレイリストのトークンを `STALE_TOKEN`、`plan_id = None`、`needs_report = false`、`adopt_pending = false`）を 1 回の保存で行う。外れた曲・プレイリストは state から外すだけで、ファイルもミュージック.app の track も消さない（管理外）。間で落ちたら、次の `sync` が回復の後・manifest の取得の前に続きを行う。`status` は途中の引き継ぎを出す
4. **state と `agent_proto::ManifestItem` に `rel_path` / `source` を必須で足す**（[D-103](D-103.md) の 7 のとおり）。`STATE_VERSION` と `PROTO_VERSION` は 1 のまま（本番の Mac は pair 前）。追加・更新は manifest の同じ `track_id` の項目から値を取り、無ければその操作を項目のエラーにする。`PendingOp` は任意、`BatchMember` は必須で持ち、回復で写す
5. **同期の近道**: `Update`（`from` 無し）で、state の曲のトークンが `ADOPTED_TOKEN`、パスの鍵・size・sha256 が計画の項目と一致すれば、受け取りもミュージック.app の操作もせずにトークン（と `rel_path` / `source`）だけ書き換える。報告はそのトークンで行い、計画に含まれるので検証を通る。受け取らないので、実行前の空き容量の確認からも外す（近道と同じ判定を使う）
6. **`--adopt` 無しの uuid 不一致は今どおり止め、文言で `pair --adopt` を案内する**

**理由**: 報告の検証はハッシュ待ちの間 desired が空で通らず、DB を作り直した直後の状態を検証の例外で通すより、引き継ぎ専用の API が前提（報告を一度も受けていない、open な計画が無い）を確かめてキャッシュを書く方が、通る経路が狭く説明がつく。結果は Android の引き継ぎ（書き直した manifest を走査で取り込む）と同じになる。uuid をサーバ側で差し替えると、`.spindle-device` と state の uuid を変えないので、エージェントの途中で落ちたときの再開に印と state の食い違いの手当てが要らない（`adopt_pending` の続きだけでよい）。プレイリストのトークンを `STALE_TOKEN` にするのはミュージック.app のプレイリストの中身の書き直しが曲の転送に比べて安いからで、サーバとエージェントで揃えるので最初の同期で同じ名前のまま中身を入れ直す。断った pair でコードを消費しないのは、端末タブでコードを発行し直す手間を増やさないため。

**却下**:
- エージェントが新しい行の uuid を受け入れて state と `.spindle-device` を書き換える: 印・state・サーバの 3 か所を揃える途中で落ちる場合の手当てが要り、印の照合（別の端末の root を守る）を緩めることになる
- [D-103](D-103.md) の 7 のとおり付け替えた state を `report_only` で報告し、検証に引き継ぎの例外を設ける: 例外が報告の経路全体に効き、通る範囲が広がる。desired が空の間は例外なしでは通らない
- `--adopt` 無しの uuid 不一致をコードの消費前に検出する: 同じ端末の pair し直し（コードを発行し直したとき）と区別できない。文言で案内するだけにする
