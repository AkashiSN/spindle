# D-97 ReplayGain は解析の後に自動でタグへ書き、Derived はその書き込みの後に作る

**決定**（2026-09-29。ユーザ依頼）:

- **`[replaygain].write_tags = true` なら、解析の後に自動でタグへ書く。** 書くべき行は `tracks.rg_write_due`
  （0004 で追加）の印で持つ。印は rg の保存で確認が成り立たなくなった行と、album gain を off にして album の値を
  消した行に立ち、書き込みの編集バッチを記録したとき（一致済みで `rg_written_at` だけ立てた行も）に下りる。
  巻き戻し・外部の変更では立たない（解析し直すまで書き直さない。書き直すと巻き戻しが効かない。ファイルが正）。
  印が立った後に**外部ツールが RG のキーを書き換えた**ことを走査が見つけたら（取り込み前の DB の RG のキーの値と
  比べる）、印を下ろす（外部の値を自動書き込みで上書きしない）。RG 以外のタグだけが変わった行は印を残す
- 印を書くのは新しいジョブ `rgwrite`（0004 で `jobs.type` に足す）。**Library 全体で 1 本**（dedup `rgwrite`、
  payload は空）で、実行時に印の付いた active な行を album ごとにまとめ、手動の `POST /api/rg/write` と同じ
  `Editor::prepare_rg_write` で **album ごとに 1 つの編集バッチ**を作る（旧値の記録・overlay・巻き戻しはタグ編集と
  共通。[D-48](D-048.md)）。album の無い行は 1 行ずつ
- 同じ album を解析する rg が queued / running の album と、反映待ちの編集がある album は後回しにし、書ける
  album を書いた後で**キー付きの後継を 2 秒後に 1 本積んで終わる**（album gain が off の album は曲ごとに解析される
  ので出揃ってから 1 バッチにする。飛ばすと書き漏れ、rg 自体を待たせると重い再解析がやり直しになる）。キーを
  外した自分を `Requeue` すると、rg の完了ごとに積まれるキー付きのジョブと別に待機ジョブが増え続ける（codex
  レビュー）。後継は dedup で常に 1 本
- 待つ判定とバッチの記録は別のトランザクションなので、その間に始まった rg が値を変えれば 1 回余分に書くことが
  ある。値が変わった行は保存で印が立ち直すので次の rgwrite で揃う（最終的な値は収束する。厳密な「1 album
  1 バッチ」の保証より、Editor の編集バッチの経路を共通に保つ方を取る）
- **`rgwrite` は開始時に自分の dedup キーを外す**（`db::jobs::release_dedup_key`）。対象を読んだ後に立った印の
  ための投入は、実行中のジョブへ合流せず新しいジョブになる（合流すると読み終えた対象に吸われて消える）
- 積むのは印を立てた書き手（rg の保存・album gain の API・Inbox の配置）。取りこぼしの回収として scan の完了
  （missing から戻った行）と起動時（`write_tags` を有効にした直後）に、印が残っていれば積む
- `write_tags = false` は「タグに一切書かない」（自動も手動も。手動は従来どおり 409 `rg_write_disabled`）。印は
  残り、有効にした後の起動時に書く
- **Derived はどの系統も RG が揃ってから作る。** 解析済みで、`write_tags` なら Library のタグへの書き込みも
  確認済み（`rg_written_at >= rg_scanned_at`）。`derived::eligible` の条件で、揃わない間は凍結と同じく既存の行と
  ファイルに触らない。設定は起動時に `derived_variants.rg_write_required` へ写す（[D-75](D-075.md) の系統設定と同じ流儀）。
  順序は rg → rgwrite → tagwrite の applied（`enqueue_if_stale`）→ transcode
- **確認時刻 `rg_written_at` は `rg_scanned_at` より小さくしない**（`set_written` / `sync_written_at` / 同じ値の
  再解析）。`rg_scanned_at` は album gain の切り替えや同じ秒の再解析で「前の値 + 1」へ進み壁時計より先にありうる
  ので、同じ秒の確認が「未書き込み」に見えて Derived が止まる
- **スキャンで新規に登録したトラックにも rg を積む**（album の照合の後、`enqueue_analysis` の規則で）。既存の
  未解析の行は拾わない。Inbox を通さずに SMB で置いた曲も漏れなく乗せるため
- 操作タブの手動ボタンは両方残す。「ReplayGain を解析」は既存の未解析の曲・測り直し用、「解析値をタグに書き直す」
  は自動で書かれなかった行（デプロイ直後の既存の未書き込み・外部の書き換え・巻き戻し後）用

**理由**: 解析と書き込みが別の手動操作だったため、書き込みを忘れた曲が Library に残り、Derived（opus の `R128_*`、
aac の焼き込み）は DB の値で作られるので Library のタグとずれていても気づけなかった。Derived を書き込みの後に
回すと、再解析で値が変わったときの aac の作り直しも 1 回で済む（従来は解析時の Encode と書き込み時の Retag の 2 回）。
書き込みを編集バッチに載せたままなので不変条件 3・4 はそのまま満たす。対象を行の印で持つのは、ジョブの payload
（album の範囲や解析時刻の下限）で持つと、album の移動・missing・実行中のジョブへの合流・同じ秒の境界で
書き漏れや書き過ぎが起きるため（codex レビュー）。

**却下**:
- rg ジョブの中で直接バッチを作る（反映待ちの行を飛ばすと書き漏れ、待つと解析のやり直しになる）
- rg ジョブ 1 本 = 1 バッチ（album gain が off の album は曲ごとの解析なので、全曲の解析で曲数ぶんのバッチが並ぶ）
- `POST /api/rg` の 1 回 = 1 バッチ（全ジョブの完了を集約する仕組みが要り、途中の失敗の扱いが複雑）
- album 単位の rgwrite に解析時刻の下限（`since`）を持たせる（上の書き漏れ・書き過ぎ。最初の実装で codex が指摘）
- 巻き戻し・外部の変更で未書き込みになった行を自動で書き直す（巻き戻しが効かない。外部の値を上書きする）
- Derived を解析だけで作る（Library のタグに書く前の値の Derived が配られ、書き込み後にもう一度作り直す）

**影響**:
- [D-47](D-047.md) の「scan 完了時の自動投入」の却下は、新規に登録した行に限って改める（移行直後の全曲解析の懸念は
  「既存の未解析を拾わない」で避ける。ただし DB を作り直した直後の走査では全曲が新規なので全曲の解析が積まれる。
  ファイルが正・DB はキャッシュの前提から、解析値を失った DB ではこれが正しい）
- opus も RG が揃うまで作らない（従来は RG 不要）。音声が差し替わった曲は再解析 → 書き込みの後に作り直す
- album gain を off にした album は、ファイルの album のキーを消す書き込みの後に Derived が追随する
- デプロイ直後、既存の「解析済みで未書き込み」の曲は印が無いので自動では書かれず、Derived の追随が止まる（既存の
  Derived は凍結されて配られ続ける）。一覧の `rg_unwritten` で絞り込んで「解析値をタグに書き直す」を一度実行する
- Inbox の件の段（[D-95](D-095.md) の可視化 B）: 「RG」は書き込みが要る設定なら書き込みまで済んで完了、系統の段の母数は
  RG が揃えば作る曲（`derived::covered`。RG 待ちも「これから作る」に数える）
- 持ち越し: 端末配信の待ちの理由（`Wait::RgPending`「RG 未解析」）は aac の解析だけを見ている。hold になる点は
  同じだが、表示を「未解析・未書き込み」に揃えるのは P5-2 の `devices.rs` の改修と合わせる
