## D-96 検証バッジは一致したかだけを出し、手法ごとの結果はプロパティと照合ジョブの結果に出す

**決定**（2026-09-29。ユーザ依頼）:

- バッジの ✔ は `verified_ctdb` / `verified_ar` を区別せず「検証済み」の 1 つにする。`tracks.verification` の
  値と写像（CTDB 優先。§7.3）は変えない（スマートプレイリストの `%verification%` もそのまま）
- どちらで一致したかは `GET /api/tracks/:id` の `detail.verifications`（手法ごとの最新の
  `album_verifications` × `track_verifications`）から、プロパティの General に「CTDB」「AccurateRip」の行で出す
- `verify` ジョブは結果 1 行を `jobs.note` に残す（ディスク × 手法の一致数と信頼度 / 登録なし / 検証不能・
  照合しなかった理由）。結果 1 行は記録と同じトランザクションで書き、commit の後に落ちた再実行はそれを返す。操作タブは投入した
  ジョブを終わるまで 2 秒ごとに `GET /api/jobs?type=verify` で追い、終わったアルバムから 1 行ずつ出す。
  一覧は状態ごとに件数の上限があるので、見えた状態をジョブ id ごとに貯め、終端が見えていないジョブは verify の
  待ち・実行中（`by_type`）が残る間は待ちとして数え、残っていなければ「結果を取れない」にする（完了の上限の
  外へ押し出されて終端を観測できなかったジョブで、待ち続けないため）
- 結果は選択を変えても消さない（閉じる・別の操作・次の照合で消す）。照合したアルバムの曲を選び直して
  プロパティで手法ごとの結果を見る使い方を妨げないため。行ごとに対象のアルバムを出すので取り違えない

**理由**: 両方で一致したトラックも CTDB 優先で「検証済み（CTDB）」になるため、実機の 6 ディスク（AccurateRip
でも 4 ディスク一致）がすべて CTDB だけで一致したように見えていた。AccurateRip の結果は verify.log にしか
無く、画面から見えなかった。投入時の「遡及照合を投入した: アルバム 1」は結果の出る場所も分からなかった。

**却下**: バッジを手法の組み合わせ（両方 / CTDB だけ / AccurateRip だけ）で塗り分ける（ユーザが「一致したか
だけでよい」を選んだ）。`tracks.verification` に両方一致の値を足す（マイグレーションが要り、DSL と
スマートプレイリストの値も変わる）。SSE の job イベントで追う（イベントに種別も結果も無い）。
`GET /api/jobs` に id の指定を足す（全ライブラリの投入では数千件の id が URL に載る）。
