# D-115 スマホ版は別の入口（`/m/`）・別のビルドで作り、PC 版に手を入れない

**背景**（2026-10-19）: いまの UI はデスクトップ専用（[SPEC §12](../spec/12-ui/README.md)）で、外出先のスマホからライブラリを眺める・探す・試し聴きする・
誤字を直す・プレイリストを手直しする・YouTube 購読の同期を押す、ができなかった。ユーザの条件は「PC 用のページを触らずに、
まったく影響を与えずに作る」こと。外出先は LTE + Cloudflare Zero Trust 経由で、ハイレゾ FLAC（1 曲 100 MB 近い）をそのまま
流せない。

**決定**:

1. **別入口・別ビルド**: コードは `web/src/mobile/`、ビルドは PC と別の vite 設定で `web/dist/m/` に出す。PC の
   `components/` `hooks/` `App.tsx` `main.tsx` `index.css` `vite.config.ts` は import も編集もしない。`api/` と `lib/` は
   編集せず import だけ。受け入れは `dist/m/` 以外の出力のファイル単位の同一（`scripts/pc-dist-hash.sh`）。配色は PC と同じ値を
   スマホ側の CSS に持ち、テーマの保存値だけ共有する
2. **機能範囲**: 載せるのは ライブラリ / フォルダ / プレイリスト（普通とスマートの作成・編集・削除）/ 購読（手動同期と進捗）、
   曲のシート、1 曲のタグの値の修正、試し聴き。**載せない**: 一括編集、リネーム、巻き戻し、CD、Inbox の承認、端末同期、
   ジョブ、記録、設定、購読の追加・変更・削除、フィールドの追加・削除、バックグラウンド再生・ロック画面・キュー、
   PWA のオフライン動作
3. **UA で `/` を振り分ける**: `Mobi` / `Android` / `iPhone` を含む UA の `/` を 302 で `/m/` へ（iPad は Mac の UA なので PC）。
   「PC 版を開く」は Cookie `spindle_view=pc` を立てて `/` を開く。`/m/` を開くと Cookie を消す（PC から戻る導線は PC を
   触らないと作れないため、`/m/` を直接開く）
4. **試し聴きは軽い形式**: 原本は流さず `?transcode=opus`。Opus が鳴らない端末向けに `GET /api/stream/:id?transcode=aac`
   を足した（現在値の Derived の m4a は Range で直送、無ければ ffmpeg の ADTS を chunked で `audio/aac`、Range なし・
   `?start=`）。非可逆の原本は両方とも変換せず返す。iOS の `canPlayType` は当てにならないので、Opus が再生前にエラーに
   なったら 1 回だけ AAC で引き直す。RG は掛けない
5. **1 曲のタグの修正も履歴に載る**: PC と同じ `batch/preview` → `apply`（`ids: [id]`）を通すので `edit_batches` に載り、
   PC の「履歴」から巻き戻せる（不変条件 4）。空にする・フィールドの追加は無い（誤字直しが目的）。標準のタグの空の行を
   埋めるのは「値の修正」として許す
6. **購読は手動同期のまま、「完了」はダウンロードの終了**: `playlist_sync` の投入完了では早すぎ、ユーザが知りたいのは成功したか
   なので、投入した ytdl がすべて終わった時点を完了とする。進み具合は読み取り専用の
   `GET /api/ytmusic/subscriptions/:id/progress`（直近の `playlist_sync` と、その購読の ytdl）。投入が走行中の古い ytdl に
   dedup されて行が増えない同期があるため、この購読の queued / running の ytdl は作成時刻によらず含める
7. **DSL の引用符のエスケープ**: スマホのルール組み立ては値を `"` で囲み、値の `"` と `\` をエスケープして書く。サーバの文法
   （`dsl.pest` の `quoted`、`unescape`）は既にこれを受けるので、「値に `"` を含められない」として弾く必要が無い。[DSL](../user-guide/dsl.md) を直した

**理由**: PC のビルドに入口を足すと Rollup が共有モジュールを共通チャンクへ切り出し、PC の JS の中身が変わる。別ビルドなら
PC の成果物は変わらないことをハッシュで示せる。API を足すだけなら既存の応答は変わらず、PC のページに影響しない。UA の振り分けは
サーバで 302 にでき、PC 側に何も足さずに済む。試し聴きを Opus/AAC にするのは、外出先の帯域で原本を流さないため（[D-52](D-052.md)）。
手動同期にするのは、同期の後に Inbox の確認がいり、時間のあるときに人が押すのが前提だから。

**却下**: PC 版のレスポンシブ化（PC 版に手が入る）。購読の自動同期（確認が追いつかない）。スマホでの Inbox の承認（細かい確認は
PC で）。原本のまま試し聴き（帯域）。PC の vite 設定への入口の追加（共通チャンクで PC の成果物が変わる）。
