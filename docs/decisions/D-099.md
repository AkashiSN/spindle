# D-99 エージェント API はセッションと別の Bearer 経路にし、報告は全項目を検証してから 1 トランザクションで反映する

**背景**（2026-10-01。仕様は [§7.11](../spec/07-pipeline/11-device-delivery.md) の「iPhone（Mac の spindle-agent）」と [D-95](D-095.md)）: P5-4 で iPhone 向けに Mac の `spindle-agent` が使うサーバ側の API を作る。P5-4 を 4a（サーバ側の API と UI）/ 4b（`agent/` クレートのエンジン）/ 4c（実機 Mac での JXA の固定と macOS バイナリ）に分け、本件は 4a。以下がその決定と、仕様の空白を埋めた判断。

**決定**:

- **P5-4 の分割**: 4a = サーバ側の API と UI、4b = `agent/` クレートのエンジン（ミュージック.app の操作を trait で差し替えて試験）、4c = 実機 Mac で JXA を固定し、CI で macOS バイナリを作る（ユーザ承認済み。ssh で届く Mac がある）
- **ワイヤ型の共有**: 「manifest の型は本体と共有」を、serde だけに依存する新クレート `agent-proto`（ワークスペースメンバー）で実現する。エージェントが spindle 本体（rusqlite bundled・lofty など）に依存しないため
- **トークンのシークレットは SHA-256**: 仕様は「シークレットのハッシュ」とだけ書く。トークンのシークレットは 256 bit の乱数なので総当たりに耐え、ファイル取得のたびに argon2id（数十 ms）を払う理由が無い。セッションと同じく SHA-256 を保存し定数時間で比較する。ワンタイムコードは仕様どおり argon2id
- **試行の予約**: pair の試行は検証（argon2id）の前に書き込みトランザクションで `pair_code_attempts` を 1 増やして予約する（ログインのレート制限と同じ流儀）。並行送信で 5 回を超えさせない。5 回目の失敗でコードを失効（セレクタとハッシュを NULL）させる
- **agent のプレイリストの dest_path はプレイリスト名そのもの**（P5-1 からの持ち越し）: ミュージック.app の「spindle」フォルダ直下に同名で作るので、`device_playlist_state.dest_path` に名前を入れ、差分の「改名」判定もそれで行う。adb は従来どおり `Playlists/<name>.m3u8`
- **manifest の応答に差分を載せる**: 仕様の manifest は `items` / `playlists` だけだが、確定する計画はサーバの差分（`device_items` 基準）なので、エージェントが表示する差分がそれと食い違わないよう、サーバの差分（操作・保留・プレイリストの操作とエラー）と `plan_token` を同じ応答に載せる
- **プレイリストの中身**: manifest の各プレイリストに `tracks: [track_id]`（順序どおり）を載せる。中身の同一性はトークンが表す
- **ファイル取得の「現在のマニフェスト」は表示用スナップショット（2 秒）で引く**: 項目の有無の判定だけに使い、内容の照合は `source_hashes` の行を毎回読み直して行う。Derived の変換が続く間、要求ごとに全曲の差分を計算し直さないため。FD の中身とトークンの組がずれない性質は `source_hashes` の identity 照合が保つ
- **ファイル取得の失敗**: `If-Match` が無い → 428 `if_match_required`。弱い ETag・`*`・並記は一致とみなさない（412）。送る元の identity が行と違う・無い・symlink や通常ファイルでないものに差し替わった → 412 `source_changed` にして `source_hashes` の行を消す（次の差分の計算で `source_hash` が再投入される）
- **破棄の本文**: `POST /api/agent/plans/:id/abandon` の本文は報告と同じ `{generation, plan_id, state, errors}` に `pending_ops` / `pending_batches`（件数）を足したもの。両方 0 で state の検証が通れば、報告と同じくキャッシュを全置換して計画を `abandoned` にする
- **UI からの強制破棄を agent にも許す**: Mac が失われたときの逃げ道。`POST /api/devices/:id/plans/open/abandon {force:true}` を agent でも受け付ける（端末にもキャッシュにも触らずに閉じる）。`force` 無しの破棄は agent では 400（Mac から行う）
- **報告の本文の上限**: 10 万件の曲を載せられるよう、report と abandon だけ本文の上限を 64 MiB にする
- **実装（P5-4a）で決めたこと**:
  - ファイル取得は表示用スナップショットで先に引き、項目が無いときは厳密なスナップショットで引き直す。404 / 412 は新しいデータで決める（直前に外された曲が最大 2 秒配られることはあるが、害のない写しにとどまる）
  - 送る元が変わった・無いときの `source_hashes` の削除は条件なし（CAS しない）。最悪でも 1 回の再計算で済む
  - ロックモードでは pair も 503 にする（`auth::guard` を通る経路と揃える）
  - pair の 5 回目の失敗は、並行して届いた正しい試行より先にコードを失効させうる。安全側に倒す
  - 報告の再送は、計画が `completed` で `report_digest` が一致するときだけ 200 を返す。それ以外の終端は 409 `plan_closed`。計画の JSON を読めなければ 409 `plan_unreadable` を返し、何も変えない
  - エージェントの経路は `auth::guard` を通らない（`ClientInfo` が無い）
  - Bearer のスキームは大小文字を区別する（使うのは自前のクライアントだけ）

**理由**: エージェントはブラウザではなく、Cookie も CSRF も trusted_cidrs も持たない。セッションの経路に分岐を足すと、どちらかの検査が緩む事故が起きやすいので、`/api/agent/*` は Bearer だけで通る別の経路にし、セッション側は Bearer で通らない。報告は端末側の状態の主張なので、件数の上限と全項目の検証を済ませてから 1 トランザクションで反映し、途中までの反映を残さない（不変条件 6）。確定した計画の再送は `report_digest` で冪等にする。

**却下**:
- トークンにも argon2id を使う（256 bit の乱数には不要で、ファイル取得のたびに数十 ms を払う）
- manifest に差分を載せず、エージェントが自前で差分を出す（サーバの `device_items` 基準の差分と食い違い、表示と確定がずれる）
- ファイル取得のたびに厳密なスナップショットを取る（Derived の変換中に要求ごとの全曲の差分計算になる）
- `/api/agent` を `auth::guard` の中に置いて分岐する（セッションと Bearer の検査が混ざり、どちらかが緩む）
