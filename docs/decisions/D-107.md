## D-107 選曲の見積もりは、送る元のハッシュが無い曲を長さ × ビットレート（原本を送るなら原本の size）で推定する

**背景**（2026-10-15）: 端末の選曲タブで「全曲」を選ぶと「合計 9,162 曲・約 605.3 MB（容量未確定 9,070 曲は含まない）」と出た。
見積もりは送る元のハッシュ（`source_hashes`）の size だけを足していたが、ハッシュは同期の計画に入った曲にしか取らないので、
選曲を広げる前の見積もりでは大半の曲が数えられず、容量が桁違いに小さく見えた。

**決定**:

1. 送る元のハッシュが有効な曲は、これまでどおりその size を数える（確定）
2. ハッシュが無い・古い曲は推定して bytes に足し、その曲数を `estimated` で返す。原本を送る曲は `tracks.size`、Derived を送る曲
   （Derived がまだ無い・古い曲も、系統が有効なら作られる）は `duration_ms` × `derived_variants.bitrate` / 8
3. 長さが分からない曲と、系統が凍結で Derived の無い曲（送られない）は推定せず `unhashed` に数え、bytes に含めない
4. 画面は「合計 N 曲・約 X（うち M 曲は長さとビットレートからの推定）」と出す

**理由**: 実機の AAC 256 kbps では、ハッシュ済みの 881 曲で実際の合計 5,026 MB に対し推定 4,873 MB（差 3%。埋め込みの
アートワーク分だけ小さく出る）で、選曲を決める目安には十分。Derived を作る・ハッシュを取るのは重く、見積もりのためだけに
走らせる理由はない。差分画面の送る量（計画に入った曲）は推定を混ぜず、これまでどおり確定値だけを使う。
