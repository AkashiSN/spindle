## D-103 DB 全損後の保存先の引き継ぎは manifest の rel_path で id を付け替え、中身は manifest の sha256 を信じる

**背景**（2026-10-13。P5-7）: D-102 の 3 のとおり、DB を作り直すと `tracks.id` / `playlists.id` が振り直され、uuid だけを写すと端末の正本の id が別の曲・プレイリストを指す。トークンも版（`audio_version` 等）や `playlist_id` を含むので一致しない。さらに DB を作り直した直後は `source_hashes` も消えており、端末の写しが今の送る元と同じかをその場では判定できない。D-102 は `dest_path` の `canonical_key` で付け替えるとしたが、`dest_path` は Library の `rel_path` の拡張子を替えたもので、Derived では元の曲が一意に引けない（WAV → FLAC の正規化など）ため、manifest が送った元の `rel_path` を覚えているのが確実だった。

**決定**:

1. **manifest の曲に `rel_path`（Library の `tracks.rel_path`）と `source`（`SourceKind::as_str()`。`master` / `opus` / `aac`）を必須で足す**。`FORMAT` は 1 のまま（リリース前で、本番の Android は未登録）。旧 manifest は読めなくなるので、保存先を消して登録し直す。ジャーナルの `Intent` にも任意で足し（曲の `put` のみ）、回復で取り込む。移動のバッチのメンバーは必須。同期の終わり（最後の `compact` の前）に、パスのキーが今の desired と一致する項目へ今の値を書き直す（補填）
2. **remap**（`src/device/adopt.rs`、純粋関数）: 曲は `rel_path` の `canonical_key` で今の tracks（missing を除く）から 1 件引いて `track_id` を付け替え、トークンを `ADOPTED_TOKEN`（`"adopted"`）にする。`path` / `size` / `sha256` / `rel_path` / `source` は変えない。プレイリストは `Playlists/<名前>.m3u8` の名前の `canonical_key` で付け替え、トークンは `STALE_TOKEN`（m3u8 の書き直しは安い）。1 つのキーに複数の曲、1 曲に複数の項目、同名のプレイリストなど曖昧なものはどれも採らない。採らなかった項目は manifest から外して**管理外**にする（ファイルは消さない）。冪等で、回復が先に付けた `STALE_TOKEN` の曲はトークンを変えない
3. **同期の近道**: `Update` でパスが同じ、book のトークンが `ADOPTED_TOKEN`、`sha256` と `size` が操作と一致する曲は、転送もジャーナルも省いてトークンだけを書き換える。信頼の水準は日常の差分と同じ（サイズまで。中身は manifest の `sha256` を信じる。これは転送時に端末上で測って照合した値）。転送量の見積もりと空き容量の確認から外し、差分の op は `adopted`（UI は「引き継ぎの照合」）。壊れた写しは回復や `device_verify` が `STALE_TOKEN` にするので送り直される。送る元は通常の転送と同じく開いて identity を照合する（計画の後に送る元が差し替わったのに同期済みにしない。変わっていれば項目エラー + 取り直し）
4. **印の復元**: 端末に m3u8 があるのはそのプレイリストに印が付いていたからなので、付け替えたプレイリストに印を付け直す（行の作成と同じトランザクション）。付けないと `selection=playlists` の端末の最初の差分が全削除になる。`generation` は作成時の既定のまま進めない
5. **API**: 通常登録が片付けるのは、中身が `.spindle` の下だけで回復に要る物が無い（`.spindle/moving` の下にファイルが無く、ジャーナルが無いか空）前の登録の失敗の残りで、manifest が無い・読めない・空（uuid が DB に無い）ものだけ。それ以外は 409 `not_empty`（曲かプレイリストを指す manifest は `volume` 違いや uuid の形が不正でも片付けない。`.spindle/moving` に曲の唯一の実体があり、ジャーナルが回復に要り得る）で、曲を指す manifest（`volume` が一致し、uuid が DB に無いもの）は 409 `adoptable`。`POST /api/devices` に `adopt: true`（adb のみ）。`register_lock` の下で、`scan` ジョブが待ち・実行中なら 409 `library_busy` → manifest を読む（無い・読めない・`volume` 違い・空・uuid の形（32 桁の小文字 16 進）が不正・回復で manifest の不整合が見つかったときは 409 `not_adoptable`、uuid が DB にあれば 409 `uuid_registered`。端末との通信の失敗は既存のエラー応答の 502 `device_failed` / 409 `not_connected`）→ `scan` の有無と remap の入力を 1 つの読み取りトランザクションで読む（スキャン中なら 409 `library_busy`。最初の確認は早めに断るためで、正はこちら）→ 回復 → remap → `compact` → 1 トランザクションで行（manifest の uuid）と印を作る → `device_scan` を投入する。途中で落ちても remap が冪等なのでやり直せる。プレビュー `GET /api/devices/adb/adopt-preview` は読むだけ（ジャーナルは回復しないので件数は目安）で `library_busy` も返す。未登録の一覧の `volumes[].state` に `adoptable` を足す
6. **バックアップ復元で行の uuid が端末と食い違う場合の付け替えは作らない**。端末を削除（端末上のファイルには触らない）してから引き継げば同じ結果になるので、SPEC にその手順を書く
7. **P5-8（Mac の `pair --adopt`）は remap をサーバで計算する**（報告で返す部分は D-104 で改訂。サーバの行の uuid を差し替え、adopt API がキャッシュを直接書く）。エージェントは state の `(track_id, path, rel_path, source)` とプレイリスト名を送り、付け替え表を受け取って state のキーを直し、`needs_report = true` で `report_only` する。pending が残っていれば拒否し、`--adopt` 無しの uuid 不一致は今どおり止める。state と `agent_proto` の項目にも `rel_path` / `source` を必須で足す
8. **id の再利用は GC が `tracks` の最大 id の行を消さないことで防ぐ**（SQLite は `max(rowid)+1` を振る）。プレイリストの id の再利用は受け入れる（Update = 改名として収束し、失う情報が無い）。どちらも今回は作らず、SPEC §17 と TASKS に残す

**理由**: 付け替えの鍵を manifest 自身に持たせると、DB が空でも端末だけで曲を引ける。`FORMAT` を上げて旧版を読む経路を作るより、リリース前なので旧 manifest を読めなくして保存先を作り直す方が単純で、読めない経路が残らない。トークンを `ADOPTED_TOKEN` にして近道を設けるのは、全曲（約 9,000 曲、初回およそ 2 時間）の送り直しを避けるため。信頼の水準を日常の差分に揃えるので、新しい信頼の穴は作らない。remap をサーバ側の純粋関数にすると、Mac も同じ規則を使える。

**却下**:
- uuid を新しい行に写すだけ（D-102 で却下済み）: 全曲が誤った更新・移動になる
- 端末で sha256 を測り直して今の送る元と照合する: 全曲の読み出しが要り、DB を作り直した直後は送る元のハッシュも無い
- 引き継ぎをジョブにして、先に送る元をハッシュしてから照合する: 登録が長いジョブになり、途中状態の扱いが増える。manifest の `sha256` は転送時に端末上で測った値で、日常の差分と同じ水準で足りる
- 全曲を送り直す: 数時間と、端末・スナップショットの書き込みが無駄になる
- `rel_path` が manifest に無い旧 manifest を、パスなどから推測して引き継ぐ経路を残す: `dest_path` から元の曲を逆引きすると誤りうる。推測の経路が残ると、誤った付け替えで他人のファイルを上書きする
- 外れた写しを差分で削除する: 「manifest に無いファイルには触らない」に例外を作る。管理外に残して手で扱う
- token・sha256・パスがすべて違う既存の写しを Delete + Add にして id の再利用を防ぐ: Library で一括にタグを直して改名するのは正当な日常操作で、そのたびに Mac の再生回数が消える
