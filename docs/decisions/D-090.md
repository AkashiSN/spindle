# D-90 却下した Inbox の件は「削除」で破棄待ちにし、GC が retention 日後に消す

**決定**（2026-09-25。P4-22。ユーザの決定: 「却下した後に Inbox に残っている行を削除したら GC で削除対象にする」）:

- 二段にする。**却下**（従来どおり。ファイルは残し「下書きに戻す」で戻せる）と、却下した件の**削除**（破棄待ち）。
  削除は `inbox_items.discard_requested_at` に時刻を入れるだけで、ファイルは消さない（旧マイグレーション 0002。[D-88](D-088.md) 追記で `0001_init.sql` へ統合。
  状態は `rejected` のままにして CHECK の作り直しを避けた）。`POST /api/inbox/:id/discard` / `/undiscard`
- **物理削除は GC だけ**（CLAUDE.md の禁止事項）。GC の区分 F: `rejected` で `discard_requested_at <= now -
  [gc].retention_days` の件。消すのは件のディレクトリの直下の**走査が写した音声**（`inbox_files` と stat が一致する
  もの）・既知の同梱ファイル（`cd::riplog::is_companion_name`。配置が Library へ持っていくものと同じ）・サイドカー
  （確かめたときと同じもの）だけ。ディレクトリは空になったときだけ消す。サブディレクトリ（別の件）・symlink・
  知らないファイルには触らない。Inbox 直下の件（`rel_dir` が空）は音声だけ。猶予は Library の論理削除と同じ
  `retention_days`（別の設定を増やさない）
- **破棄待ちの間にファイルが変わったら消さない**（安全側）。走査が変化（足された・差し替えられた）を見たら破棄待ちを
  解き、`rejected` のまま `error` に理由を残す（`pending` には戻さない: 却下は人の判断で、戻すと上部バーの件数に
  出て承認を促してしまう。見直して要らなければもう一度削除する）。GC は**確かめ → 削除**の 2 段: 確かめの段で
  直下の音声を `inbox_files` と照合し（写した後に足された・変わったもの）、同梱ファイルとサイドカーは
  `inbox_files` に写らないので **ctime が「破棄の要求の秒 − 1」以降**なら要求の後に置かれた・変えられたものとみなす
  （境目は安全側に「後」。1 秒の余裕は、要求の時刻が実時刻の秒なのに ctime はカーネルの粗い時計で数 ms 遅れて付き、
  要求の直後に置いたファイルが要求の前の秒に見えることがあるため。試験で約 1/8 の頻度で見逃しを再現した。2026-09-25）。どれかが外れたら何も消さずに同じく解く。削除の段は 1 本ずつ、消す直前に確かめの
  段の stat（inode / size / mtime / ctime）と照合し、外れたらそこで止めて解く（それまでに消したのは確かめ済みの
  ものだけ）。NotFound 以外で消せなければそこで止めて**行と破棄待ちを残す**（成功扱いにしない。次の GC で続きを
  行う。消えたファイルは NotFound として飛ばす）。どちらの場合も行は消さない（codex レビューの指摘）
- `rejected` から出る遷移（下書きに戻す）は破棄待ちを解く（`transition` / `set_state` が `discard_requested_at` を
  NULL にする）
- GC の実行は件ごとに書き込みのトランザクションの中で「まだ rejected で期限が来ているか」を確かめ直し、ファイルを
  消してから行を消す。取り消しの API も同じ writer を通るので、確かめてから消すまでの間に取り消されることはない
- 画面: 一覧は従来どおり却下した件もバッジ付きで出す（SPEC の「一覧から外す」は実装と違っていたので直した）。
  却下した件に「削除」（確認ダイアログに消す時期）、破棄待ちには「削除待ち」のバッジと期限、「削除を取り消す」。
  期限は `GET /api/inbox` の `discard_retention_days` から

**理由**: 却下した件のファイルは Inbox に残り続け、人が SMB で消すしかなかった（リハーサルで VALIS の二重取り込みを
却下した後に観測）。却下 = 即削除にすると、下書きに戻して承認し直す道が消え、物理削除が GC 以外の経路に出る。
二段にして GC に任せれば、人が「要らない」と明示した件だけが猶予の後に消える。

**却下**: 却下と同時に削除する（戻せない）。確認ダイアログで即時に消す（物理削除が GC 以外に出る）。却下した件を
すべて GC の対象にする（「却下したが後で見直したい」件まで消える）。破棄待ちの専用の状態を足す（CHECK の作り直しが
要り、`rejected` と別に扱う箇所が増える）。
