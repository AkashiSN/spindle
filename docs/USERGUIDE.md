# 操作手順

spindle の画面の使い方。起動・更新・バックアップは `OPERATIONS.md`、旧ライブラリからの移行は
`MIGRATION.md`、スマートプレイリストの文法は `DSL.md` を見る。画面の仕様そのものは `SPEC.md` §12。

## 1. 初回起動とログイン

1. `deploy/compose.yaml` を TrueNAS のカスタムアプリとして起動する（作り方は `OPERATIONS.md`
   「イメージの更新」）。初回だけ環境変数 `SPINDLE_INITIAL_PASSWORD` を渡す。パスワードは
   argon2id で DB に保存され、以後この環境変数は読まれない
2. ブラウザで `http://<ホスト>:8080/` を開き、パスワードを入れてログインする（ユーザ名は無い）。
   セッションは Cookie で保持される
3. ログイン後は「ライブラリ」画面が開く。起動時にライブラリのスキャンが自動で走るので、
   ☰ →「ジョブ」の `scan` が完了すると全曲が表に出る

初期化が済んだら compose から `SPINDLE_INITIAL_PASSWORD` の行を消してよい（平文を残さないため。
消しても DB のパスワードで起動する）。環境変数も DB もパスワードが無いと**ロックモード**で起動し、
`/health` 以外は 503 を返す。そのときはログイン画面に「パスワードが未設定です」と出る。

ログインに何度も失敗すると IP 単位でしばらく拒否される（「試行回数が多すぎます」）。

## 2. 画面の骨格

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ spindle  ライブラリ アルバム CD YouTube Inbox❷ │ ⏮ ▶ ⏭ ■ シーク 曲名 │ RG 原本 🔊 │ ☰ │  ← 上部バー
├──────────────┬───────────────────────────────────────────────────────────────┤
│ [検索]       │ プロパティ │ 一括編集 │ 操作              選択 N 件 ▴ │  ← 右パネル
│ ▾ ツリー     ├───────────────────────────────────────────────────────────────┤
│ プレイリスト  │ 表示 K 件                                            列 │
│ フィルタ      │ ☐ │ # │ Title │ Artist │ Album │ … │ 長さ │ バッジ │        │  ← 表
│ [cover]      │   （仮想スクロール）                                          │
└──────────────┴───────────────────────────────────────────────────────────────┘
```

- **上部バー**: 左が画面の切替。「ライブラリ」がホームで、その右に取り込みの入口（CD / YouTube）、
  さらに右が「Inbox」。**取り込むと Inbox に赤い数字（承認待ちの件数）が増える**ので、次にどこを
  見ればよいか分かる。中央がプレイヤー（§8）。右端の ☰ に「ジョブ」「履歴」「設定」「ログアウト」
  （ジョブには実行中 + 待ちの件数が付き、失敗があれば ☰ 自体に赤点が付く）。☰ の横の点は
  サーバとの SSE 接続状態（緑なら接続中。切れても自動で再接続する）
- **左サイドバー**: 検索ボックス、ツリー、プレイリスト、固定フィルタ、選択中の曲のアートワーク。
  どれを選んでも**中央の表の集合を差し替えるだけ**で、列・ソート・選択の仕組みは共通。
  ツリーが効かない画面（CD / YouTube / Inbox / ジョブ / 履歴 / 設定）では出ない
- **表**: 全曲（最大数万行）を仮想スクロールで出す。列は右上の「列」で表示 / 非表示と順序を変え、
  ヘッダのクリックでソート、ドラッグで並べ替え・幅変更。設定はこのブラウザに保存される
- **右パネル**: 「プロパティ」「一括編集」「操作」の 3 タブ。頭に「選択 N 件（うち反映待ち M 件）」。
  ▴ で折りたたみ、境界のドラッグで幅を変えられる（保存される）

## 3. 一覧の使い方

### 3.1 絞り込み

- **検索**: サイドバー先頭の検索ボックス。入力から 250ms 後に表へ反映する。3 文字以上は部分一致
  （全文検索）、2 文字以下は前後一致なしの LIKE（短い語は当たりにくい）
- **ツリー**: 既定は Category → AlbumArtist → Album。表示形式は組み込み 5 種（by folder structure /
  by category / by artist / by album / by year）と、`%category%|%albumartist%|%album%` のような
  パターンで自作できる（「新しい表示形式…」。`|` が階層の区切り）。節を選ぶとその範囲に絞る
- **プレイリスト**: 選ぶとその内容だけになる（§7）
- **固定フィルタ**: 未検証 / 重複 / missing / RG なし / RG 未書込 / 反映待ち / conflict / hardlink /
  FLAC 未検査 / FLAC エラー / Hi-Res 未検査 / 偽ハイレゾ疑い。複数を押すと AND。ツリーや検索と
  組み合わせられる

絞り込みを変えても**選択集合は変わらない**（§3.2）。

### 3.2 選択

一括編集も操作もすべて「選択」に対して行う。

| 操作 | 動き |
|---|---|
| クリック | その行だけを選択（カーソルも置く） |
| Shift + クリック | 直前の行からの範囲を**足す** |
| Ctrl + クリック / Space | 1 行をトグル |
| Ctrl+A | 表示中の絞り込み結果を**全件**選択（何万件でも即時。ID ではなくフィルタ式を持つ） |
| Esc | 選択解除 |
| ↓ ↑ / PageDown PageUp / Home End | カーソルを動かし、その行だけを選択 |
| Shift + 上記 | anchor からカーソルまでの範囲そのものに置き換える（戻せば縮む） |
| Ctrl + 上記 | カーソルだけ動かす（選択は変えない） |
| Delete | プレイリストを開いているとき、選択をそのプレイリストから除外 |

選択は作った時点で固定される。その後に検索語やツリー、ソートを変えても選択集合は変わらないので、
表に見えている行と選択が食い違うことがある。右パネルの「選択 N 件」が正。

### 3.3 バッジ列

1 セルに複数のアイコンが並ぶ。カーソルを合わせると文言が出る。凡例は表の上の「凡例」から。

| バッジ | 意味 |
|---|---|
| ✔ / ✘ / ○ / · | CD 由来の照合。検証済み（AccurateRip / CTDB）/ 不一致 / 検証不能（配信・ダウンロード音源）/ 未検証 |
| L / l | 可逆 / 非可逆（コーデック名はツールチップ） |
| RG | ReplayGain 書き込み済み。薄い表示は計測済みだがタグ未書き込み |
| D / D• | Derived（配布用 Opus）あり。• はタグが古く追随待ち |
| F / ✘F | FLAC の STREAMINFO に MD5 が無い / デコードエラー |
| H | 偽ハイレゾ検出の疑い・判定できず・エラー（色で区別。• は結果が古い） |
| ⏳ | 編集の反映待ち（バッチが処理中）。この行は編集できない |
| ⚠ | conflict。外部の変更と衝突して最後の編集が反映されなかった（履歴画面で現在値を確認） |
| ⧉ | 同一音声の重複がある |
| ∅ | missing。ファイルが見つからない（行はグレー。7 日後に GC が消す） |

### 3.4 その場で直す

- セルをダブルクリックすると 1 件だけの編集になる（Enter で適用、Esc で取り消し）。裏では 1 件の
  バッチとして同じ経路を通るので、履歴に載り巻き戻せる
- 行の先頭に出る ▶ で、その行から表示順に連続再生する（§8）

## 4. プロパティタブ

選択した行のタグ（Metadata）、ファイル情報（Location）、技術情報（General）を出す。複数選択なら共通の
値だけを出し、違う値は「<複数の値>」になる。

- 値をダブルクリックすると編集欄になり、Enter で**選択全体**にその値を書く（`;` で多値）
- 行末の × か右クリックで、そのフィールドを選択全体から削除する（値の無い行は消せない）
- 表の下の「フィールドを追加」で新しいキーに値を書く（キーは大文字化。`=` と制御文字、`PICTURE` は不可。
  既にあるキーはその行を編集する）

どれも 1 操作のバッチになり、プレビュー → 適用 → 履歴と同じ流れで反映される。

## 5. 一括編集タブ

選択した全曲に同じ操作の列を適用する。foobar2000 の Masstagger に相当。

1. 「追加する操作」から種類を選び、キーと値を入れる。上から順に適用される（上へ / 下へで並べ替え）
   - **固定値**: キーに値を書く（`;` で多値。空なら削除）
   - **フィールド参照**: `%artist%` のように他のフィールドの値を写す（テンプレート）
   - **正規表現置換**: パターンと置換（`$1` で参照）
   - **連番**: TRACKNUMBER などを現在のソート順に振り直す（開始番号を指定）
   - **削除**: キーを消す
2. 「プレビュー」を押すと、表の該当セルに 旧値 → 新値 の差分が重なる。頭に「変更 N / 変更なし M /
   反映待ちで除外 K」
3. 説明（任意。履歴に残る）を入れて「適用」。バッチが作られ、ジョブがファイルへ書く。表のバッジが
   ⏳ → 消える、で完了。件数が多ければ「ジョブ」画面で進捗が見える

操作リストは選択を変えても残るので、同じ操作を別の集合へ繰り返し適用できる。選択・操作・ソートを
変えたら**プレビューし直す**（プレビュー時の集合に対してだけ適用される）。

対象に反映待ち（⏳）の行があると適用できない。「M 件を除外して適用」か、待ってから再度プレビューする。

画像はタグ編集の対象外（アートワークは操作タブの「アートワーク」で差し替える）。

## 6. 編集履歴と巻き戻し

☰ → 「履歴」。タグ編集・リネーム・正規化・MD5 補填・アートワーク差し替え・購読の番号揃えなど、
ファイルを書き換えた操作はすべてバッチとしてここに並ぶ。

- 行を開くと、曲ごとの結果（applied / skipped_conflict / failed）と変更内容が見える。conflict の行は
  「ファイルを再読込した現在値」を並べて出す
- 「巻き戻す」は終端状態（applied / partial / failed）のバッチにだけ押せる。巻き戻しも新しいバッチとして
  同じ一覧に現れる（↩ で元バッチを示す）。戻したものを「巻き戻す (=やり直し)」でもう一度戻せる
- 戻し済みのバッチは「#N で戻し済み」と表示され、再度は戻せない
- 巻き戻しの時点でファイルが元バッチの結果と違っていれば（外部で書き換えた等）、その曲だけ conflict と
  なり他は戻る。直してから再度巻き戻すと残りだけが対象になる
- 処理中（prepared / applying）のバッチは「キャンセル」できる

外部の変更（foobar2000 で書いた等）は次のスキャンで取り込まれ、DB ではなく**ファイルの内容が採用**される。
編集と外部変更がぶつかったときは、編集側が conflict になる。

## 7. 操作タブ

選択した曲に対する、タグ編集以外の操作。ボタンごとにジョブか編集バッチが作られる。

### ファイル

- **リネームをプレビュー**: `config.toml` の `[layout]` の規則でパスを組み直し、旧 → 新を一覧に出す。
  生成できない行（必要なタグが無い、宛先が衝突）は理由付きで赤くなる。「リネームを適用」で
  ファイルを移動する（履歴に載り巻き戻せる。Derived は自動で追随する）。同じ名前・同じ年の別の版（通常版と
  Hi-Res 版など）が同じフォルダに当たるときは、区別したい側の曲に `EDITION` タグ（例: `Hi-Res`）を付けると
  `アルバム名 (Hi-Res)` に分かれる（付けていない方は元の名前のまま）
- **正規化をプレビュー**: WAV / ALAC / AIFF を FLAC にする。適用すると元ファイルは `Archive/` へ退避
  され（すぐには消えない。設定画面の「退避ファイル」から復元できる）、変換前後の PCM が一致するときだけ
  置き換わる。既に FLAC の行や非可逆は「変更なし」

### ReplayGain / FLAC

- **ReplayGain を解析**: 曲ごと（album gain が on の album は album 単位）にラウドネスを計測する。
  ファイルは書かない。バッジが薄い RG になる
- **解析値をタグに書く**: 計測済みの値をタグに書く編集バッチ（巻き戻せる）。Opus は R128 形式で書く
- **album gain**: 選択行が属する album ごとのチェック。on にすると album 単位で解析し直し、通し再生の
  ゲインが付く。off にすると album の値を消す。既定は off（CD 取り込みは on）
- **FLAC を検査**: `flac -t` と MD5 の有無を確認する（読むだけ）。結果はバッジ F / ✘F と固定フィルタ
- **MD5 を補填**: 検査で MD5 無しだった FLAC の STREAMINFO に MD5 を書く（巻き戻せる）
- **偽ハイレゾを検出**: 可逆かつ 48 kHz 超または 16 bit 超の曲を解析し、アップサンプリングやビット深度の
  水増しを判定する（読むだけ。結果はバッジ H とプロパティの「Hi-Res check」）
- **遡及照合**: 44.1 kHz / 16 bit / 2ch の FLAC だけが対象。アルバム単位で CTDB / AccurateRip に照会し、
  CD 由来の音源かどうかを格付けする。不一致は「要確認」で不良とは限らない（ログは `data/verify/`）

### アートワーク

画像ファイル（JPEG / PNG / WebP）を選ぶとプレビューが出る。「選択の埋め込み画像を差し替え」で選択した
全曲の埋め込み画像をこの 1 枚に置き換える（編集バッチ。巻き戻すと元の画像に戻る）。同梱の
`cover.jpg` 等は書かない（埋め込みに統一）。

### プレイリスト

「プレイリストへ追加…」で選択を手動プレイリストの末尾に足す（表からのドラッグでも同じ）。

## 8. プレイリスト

サイドバーの「プレイリスト」区画。

- **手動プレイリスト**: 「新しいプレイリスト」で作る。表の行をプレイリスト名へドラッグして追加、
  プレイリストを開いた状態で行をドラッグして並べ替え、「…から除外」ボタンか Delete キーで外す
- **スマートプレイリスト**（⚙）: 「新しいスマートプレイリスト」でルールを書く。中央にエディタが出て、
  入力しながら件数と表の結果が追随する（Ctrl+Enter で保存）。例:
  `%albumartist% IS ヰ世界情緒 AND NOT %category% IS _Unsorted ORDER BY %date% DESC LIMIT 100`。
  文法は `DSL.md`。ライブラリが変わると自動で再評価される（「再評価」で手動も可）。
  項目の追加・並べ替えはできない
- **メニュー**（行末の「操作」）: 改名 / 削除 / ルールを編集 / 再評価 / foobar クエリ / 書き出し
- **書き出し**: プロファイル（foobar / android / internal）を選ぶと `Playlists/<profile>/<名前>.m3u8`
  に書く。パスの形はプロファイルごと（foobar は Windows のドライブレター、android は Derived への
  相対パス）。Derived のタグが古い曲があれば件数が通知に出る。一度書き出したプレイリストは、
  内容が変わると自動で書き直される
- **foobar クエリ**: スマートプレイリストのルールを foobar2000 の Autoplaylist 構文に変換して表示する
  （コピーして foobar 側に貼る。変換できない条件は脚注に出る）
- **取り込み**: 「Playlists/ の m3u8」から、Playlists ディレクトリにある m3u8 を手動プレイリストとして
  取り込む。行はパスとファイル名で照合し、見つからない行は未解決として件数に出る

## 9. 再生

上部バー中央のプレイヤー。表の行の ▶ で、その行から表示順に連続再生する。

- ⏮ ▶ ⏭ ■ とシークバー、音量
- **RG**: off / track / album。album は album gain が無ければ track にフォールバック
- **原本**: 既定では可逆の曲は Derived の Opus（48 kHz）を再生する。チェックすると原本を流す
  （ハイレゾをそのまま聴きたいとき。ブラウザが再生できない形式は ffmpeg で変換される）
- 非可逆（Opus / MP3 / AAC）は常に原本

## 10. アルバム画面

上部バーの「アルバム」。サムネイルのグリッドで、表と同じ絞り込み（ツリー・プレイリスト・検索語）が
効く。クリックすると一覧をその album に絞って戻る。missing だけの album は出ない。

アートワークは埋め込み画像か同梱画像（`cover.jpg` 等）から自動で拾う。曲ごとに画像が違う album は
曲ごとの画像を使う。

## 11. 取り込み

取り込み元は Inbox / CD / YouTube の 3 つで、結果はすべて **Inbox** に集まり、人が承認して配置する。

### 11.1 Inbox

**category**（配置先の最上位のフォルダ）の選択肢は、Library 直下のフォルダ名（Anime / J-POP など）から
スキャンで自動で作られる。新しい category を増やすときは、選択欄で名前を足すか、Library の直下に
フォルダを作ってアルバムを置けば次のスキャンで選択肢に出る（`_Unsorted` は category にならない）。
自動で作られるのは追加だけなので、SMB で一時的に作ったフォルダの名前などが残ったら、設定画面の
「category」で消す（どのアルバム・購読・Inbox の下書きにも使われていない語彙だけ消せる）。

`config.toml` の `[paths].inbox` に音声ファイルの入ったディレクトリを置くと、1 つのディレクトリが 1 つの**取り込み**として
一覧に出る（定期の確認は変化があったときだけ走査する。「今すぐ確認」で即時）。

1. 左の一覧から取り込みを選ぶ。右にアルバム単位（アルバムアーティスト / アルバム / 日付 / category）と
   トラック単位（ディスク / # / タイトル / アーティスト）の補正フォームが出る。初期値はファイルの
   タグからの提案
2. 直す。問題（必須項目が空、番号の重複など）が残っている間は「承認して配置」が押せない
   - タイトル欄の下に「⚠ Library に同名」が出たら、同じ曲を二重に取り込もうとしている可能性がある
     （Library 側とこの曲の長さが並ぶので、長さで別テイクか見分ける。Cover / Live ver. は別曲。承認は止めない）
   - ARTIST が多値のファイルは元の値をチップで示す。「ファイルの多値をそのまま保つ」を外すと 1 値で書く
   - 「album gain を計算する」: アルバム通し再生用。既定 off
   - 「宛先: …（N 曲）に追加。番号は M から」が出ていれば、既存の album に追記される。再生リストの購読から
     落とした曲は「番号 165 に入る（再生リストの位置。空けてある番号）」と出る。後ろの曲をずらす処理は承認では
     なく同期が先に済ませていて、その経緯（何曲をずらしたか・バッチ番号）が下に出る。承認しても既存の曲は動かない
   - 追記先の album の曲にディスク番号が無ければ「ディスク番号は付けない」と出て、disc 列が空になる（追記した曲
     だけが並びの末尾に回らないよう、宛先に合わせてディスク番号を書かない）
3. 「承認して配置」。inbox ジョブが Library へ移し、DB に登録し、ReplayGain / Derived を投入する。
   配置済みの取り込みは 24 時間残り、「アルバムを開く」で一覧に飛べる（画像は Library に登録された同じ画像を出す）
4. 「却下」はファイルを残したまま取り込みを却下にする（一覧に「却下」で残る）。「下書きに戻す」で承認前に戻せる
5. 要らない取り込みは、却下したうえで「削除」する。ファイルはすぐには消えず、`[gc].retention_days`（既定 7 日）
   経ったあとの GC が取り込みのディレクトリの音声・カバー画像などを消し、取り込みも一覧から消える（一覧に「削除待ち」、
   承認画面に消す日時が出る）。それまでは「削除を取り消す」で却下に戻せる。削除待ちの間にそのディレクトリへ
   ファイルが足されると、見ていないものを消さないよう削除は自動で取り消される

承認後にファイルが変わると自動で pending に戻る。

### 11.2 CD

上部バーの「CD」。吸い出しは未実装（`TASKS.md` P2-5）で、いまはディスクの読み取りとメタデータを
そろえるところまでが動く。**取り込んだものは Inbox に入る**（入力 → Inbox → ライブラリ）ので、
この画面では値を直さない。

1. CD を入れる。上に**トラックの表**が出る（曲数と長さはディスクから。照会を待たない）。同時に
   MusicBrainz へ自動で照会する。ドライブの無い環境では「詳細」の中に TOC の貼り付け欄がある
2. 下に候補が並ぶ。選ぶと表のタイトルが**実名に置き換わり**、左にジャケットが出る。まだ名前が
   入っていない行は `Track 01`… が薄く見えていて、そのまま取り込めばその名前になる
3. 照会は DiscID → ISRC / JAN・UPC → TOC 近似の順に広げ、**当たった段で止まる**。どれも違うときは
   「さらに広げて探す」で TOC の近い盤まで見る。候補に出ない盤は「詳細」のリリース URL 指定で当てる
4. 「候補から写す範囲」は既定が「全部写す」で、レーベル・カタログ番号・各トラックのタイトル /
   アーティストまで入る。表記を自分で決めたいときは「識別用の最小限」（アルバム・アルバムアーティスト・
   日付・ディスク番号 / 枚数・MB id だけ）に切り替える（トラック名は空のまま取り込まれ、Inbox で入れる）。候補が無ければそのまま手で入れる
5. 「取り込む」（P2-5 で有効になる）。**この画面は表示だけで、値は直せない。** 取り込んだものは
   Inbox に入るので、名前や配置先（category）は Inbox の承認画面で直す。どの候補も違うときは
   「どれも違う（候補を使わない）」で、名前の無いまま取り込んで Inbox で入れればよい
6. 候補を選んで取り込んだ盤は、CD 画面に出ていたジャケット（Cover Art Archive の表の画像）が Inbox の承認画面の
   画像の欄に**最初から入っている**（取り込みの後の確認で一度だけ取りに行く）。そのまま承認すれば全曲に埋め込む。
   要らなければ「画像を外す」、別の画像にするなら「差し替える…」。Cover Art Archive に画像の無い盤と、候補を
   選ばずに取り込んだ盤は画像なしのまま

### 11.3 YouTube

上部バーの「YouTube」。動画か再生リストの URL を 1 行 1 つ貼って「ダウンロード」。音声を Inbox に置く
（承認は Inbox）。再生リストは動画ごとに展開し、取り込み済み（`SOURCE_URL` が一致）の動画は飛ばす
ので、同じ再生リストを何度貼っても新しいものだけが落ちる。下の「ジョブ」表で進み具合と結果
（Inbox に置いた / プラグインが skip / 失敗の理由）が見え、Inbox に置いた行は「Inbox で確認」で飛べる。

URL を貼る手間を減らすブックマークレット（ブックマークの URL 欄に貼る。`<spindle>` は
`http://truenas:8080` のような spindle の URL）:

- **この動画を spindle へ**: いま見ているページの URL を spindle の YouTube 画面に入れて開く
  ```
  javascript:void(open('http://<spindle>/youtube?url='+encodeURIComponent(location.href)))
  ```
- **このページの動画リンクを全部集める**: チャンネルの動画一覧・検索結果・再生リストのページで
  動画の URL を集め、改行区切りでクリップボードへ（spindle の欄に貼る）
  ```
  javascript:(()=>{const s=new Set([...document.querySelectorAll('a[href*="/watch?v="]')].map(a=>new URL(a.href).searchParams.get('v')).filter(Boolean));navigator.clipboard.writeText([...s].map(v=>'https://www.youtube.com/watch?v='+v).join('\n')).then(()=>alert(s.size+' 件をコピーした'))})()
  ```

#### 再生リストの購読

アーティストごとに再生リストを 1 本ずつ持っているなら、URL を貼るかわりに「購読」に登録する
（再生リストの URL + 追記先のアルバムアーティスト / アルバム / category）。「同期」を押すと
（`config.toml` の `[ytmusic].sync_interval_hours` を 0 以外にすれば定期的にも）、再生リストを列挙して

1. 既に Library にある曲の `TRACKNUMBER` とファイル名を再生リストの位置に揃え（履歴に載り巻き戻せる）、
2. Library にも Inbox にも無い動画だけを位置付きでダウンロードして Inbox に置く（1 回の上限は既定 50 本）。

承認は今までどおり Inbox で行う（初期値の番号がそのまま位置）。配置されると自動でもう一度同期が走り、
番号を揃え直す。非公開・削除になった動画は位置を占め続けるので、その番号は飛ぶ（購読の結果に「取れない」
として出る。公開に戻れば次の同期で拾う）。`SOURCE_URL` の無い曲や再生リストに無い曲は触らない（その番号に
入るべき曲は「揃えられない」として出るので、手で直す）。「揃える」を外した購読は番号に触らない。

結果に詳細があれば「詳細」で行を開く。同期中は編集・削除できない。

`config.toml` の `[ytmusic].ytdlp_args` には `["--extractor-args", "youtube:lang=ja"]` を入れておく（サンプルの
既定）。言語を指定しないと、投稿者が翻訳タイトルを付けた動画は英語のタイトル（とチャンネル名）が返り、日本語の
曲名が取れない。

YouTube に弾かれるようになったら、まず yt-dlp を新しくする（イメージの更新。`OPERATIONS.md`）。それでも
駄目なら `[ytmusic].ytdlp_args` に `--extractor-args`（`youtube:lang=ja;player_client=…` のように `;` で並べる）や
`--cookies` を足す。

## 12. ジョブ画面

☰ →「ジョブ」。スキャン、タグ書き込み、ReplayGain、Derived 生成、ダウンロードなど裏で走る処理の
一覧。実行中 + 待ちの件数は ☰ のメニュー内の「ジョブ」に付き、失敗があれば ☰ 自体に赤点が付く。

- タブ: **実行中・待ち / 完了 / 失敗・取り消し / すべて**。各タブに件数
- 種別表: 種別ごとの並列度と待ち / 実行中 / 完了 / 失敗の数。クリックで一覧をその種別に絞る。表の下に
  CPU 系ジョブの共通予算（コア数）
- 各行: 対象（どのファイル / アルバム / バッチか）、進捗（done / total）、失敗理由。「再試行」
  「取り消し」、終端の行は「消す」で一覧から片付ける。「失敗をすべて消す」で赤点も消える
- 編集バッチ由来のジョブは「編集履歴で開く」で履歴画面に飛ぶ

ジョブは冪等で、コンテナの再起動や電源断のあとは中断したものが自動で再開される。

## 13. 設定画面

☰ → 「設定」。

- **表示**: 配色（OS に従う / ライト / ダーク）。このブラウザにだけ保存される
- **ライブラリ**: 「再スキャン」は stat の差分だけを見る（速い）。「deep scan」は全件のタグと音声
  ハッシュを読み直す（時間がかかる。外部で大量に書き換えた後や、DB を復元した後に）
- **GC**: 「消すものを確認（dry-run）」で、missing が保持期間（既定 7 日）を超えた行、退避期限を過ぎた元ファイル、
  Derived の孤児、参照の無いアートワーク、古いジョブ行の件数と容量を出す。確認してから「GC を実行（N 件）」。
  定期実行は 1 日 1 回（物理削除はここだけ）
- **category**: 配置先の最上位のフォルダの一覧（Library 直下のフォルダ名からスキャンで自動で作られる）。
  使われていないものは「削除」で消せる（使われていれば理由が出て消えない）。Library の直下に同じ名前の
  フォルダがあってアルバムが入っていれば、次のスキャンでまた作られる
- **退避ファイル**: 正規化で置き換えた元ファイルの台帳。「復元」で元に戻せる（期限までに）
- **config.toml**: 現在の設定の閲覧。変更はファイルを編集してコンテナを再起動する（画面からは書けない）

## 14. 困ったとき

| 症状 | 見るところ |
|---|---|
| 曲が表に出ない | ジョブ画面の `scan` が完了しているか。`[paths].library` が正しいか（設定画面の config.toml） |
| ⚠ conflict が付いた | 履歴画面でそのバッチを開き「現在値」を確認。外部の変更を取り込んだ後に再適用する |
| ⏳ が消えない | ジョブ画面で `tagwrite` / `rename` が失敗していないか。失敗理由を見て「再試行」 |
| ∅ missing が付いた | ファイルを移動・削除した。戻せば次のスキャンで復帰する。7 日（`[gc].retention_days`）で GC が行を消す |
| YouTube の取り込みが失敗する | まずイメージを更新して yt-dlp を新しくする（`OPERATIONS.md`） |
| 再生が始まらない | 「原本」を外して Derived を使う。Derived が無ければ ジョブ画面の `transcode` を待つ |
| DB が壊れた | `OPERATIONS.md`「復元」。バックアップから戻して deep scan |
